    18. Exercício prático – Versão 8

    Vamos retomar a aplicação de exemplo — versão 5 (e sua versão 7, configurada pelo arquivo JSON) — e transformá-la em uma aplicação cliente/servidor. Isso nos permitirá pôr em prática o que aprendemos no capítulo anterior sobre serviços web.

    18.1. Introdução

    A arquitetura da versão 5 era a seguinte:

    • a camada chamada [dao] (Data Access Objects) cuida das interações com o banco de dados MySQL e com o sistema de arquivos local;
    • a camada chamada [business] realiza o cálculo do imposto;
    • O script principal atua como orquestrador: ele instancia as camadas [dao] e [business], e depois se comunica com a camada [business] para executar as tarefas necessárias.

    Vamos migrar essa arquitetura para a seguinte arquitetura cliente/servidor:

    • Em [2], reutilizaremos a camada [dao] da versão 5, removendo os métodos que acessam o sistema de arquivos local. Esses métodos serão migrados para a camada [dao] do cliente [6, 7];
    • em [3], a camada [business] permanecerá igual à da versão 5, menos seu método [executeBatchTaxes], que é migrado para as camadas [business] e [8] do cliente;
    • Em [4], o script do servidor deve ser escrito; ele precisará:
      • criar as camadas [business], [dao] e [3, 2];
      • comunicar-se com o script cliente [5, 7];
    • Em [7], a camada [dao] do cliente deve ser escrita:
      • ela será um cliente HTTP do script do servidor [4, 5];
      • ela adotará os métodos de acesso ao sistema de arquivos local da camada [dao] da versão 5;
    • Em [8], a camada [business] do cliente fornecerá os mesmos métodos que a interface [InterfaceBusiness] da versão 5. No entanto, sua implementação será diferente. Na versão 5, a camada [business] realizava o cálculo do imposto. Aqui, é a camada [business] do servidor que realiza esse cálculo. A camada [business] do lado do cliente, portanto, recorrerá às camadas [dao] e [7] para se comunicar com o servidor e pedir que ele calcule o imposto;
    • Em [9], o script de console precisará instanciar as camadas do cliente [dao, business] e iniciar sua execução.

    O servidor é um script web: ele fica na pasta [scripts-web/tax/version-08] e é executado pelo servidor Apache do [Laragon]. O cliente é um script de console: ele fica na pasta [scripts-console/tax/version-08] e é executado em um terminal.

    18.2.1. Entidades trocadas entre as camadas

    As entidades trocadas entre as camadas são as da versão 5: a exceção [TaxException], os dados da administração tributária [TaxAdminData], e a descrição do banco de dados [Database]. O servidor também usa a classe [Utilities] da versão 5, cujo método [readJsonFile] é usado pela classe [Database]. O curso de PHP 7 copiava esses arquivos para a pasta do servidor. Agora os carregamos diretamente da pasta [scripts-console/tax/version-05]: isso garante que cada classe exista em uma única instância, e qualquer correção feita na versão 5 beneficia todas as versões que a utilizam.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// a camada [dao] do servidor: ela obtém os dados da administração tributária em um banco de dados
// é a classe [DaoTaxWithTaxAdminDataInDatabase] da versão 5 sem os métodos
// que trabalham com os arquivos JSON dos contribuintes
class ServerDao implements InterfaceServerDao
{
    // a descrição do banco de dados
    private readonly Database $database;
    // o objeto [TaxAdminData] que contém os dados da administração tributária
    // [protected]: as classes derivadas poderão inicializá-lo
    protected readonly TaxAdminData $taxAdminData;

    // o construtor
    public function __construct(string $databaseFilename)
    {
        // a descrição do banco de dados - pode lançar uma exceção [TaxException]
        $this->database = Database::fromJsonFile($databaseFilename);
        $database = $this->database;
        try {
            // abrimos a conexão ao banco de dados
            // as linhas lidas serão retornadas como arrays associativos [coluna => valor]
            $connection = \PDO::connect(
                $database->dsn,
                $database->id,
                $database->pwd,
                [\PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC]
            );
            // iniciamos uma transação
            $connection->beginTransaction();
            // lemos a tabela das faixas de tributação
            $brackets = $this->getBrackets($connection);
            // lemos a tabela das constantes
            $constants = $this->getConstants($connection);
            // encerramos a transação com sucesso
            $connection->commit();
        } catch (\PDOException $ex) {
            // há uma transação em andamento?
            if (isset($connection) && $connection->inTransaction()) {
                // encerramos a transação com falha
                $connection->rollBack();
            }
            // repassamos o erro ao código chamador como uma exceção [TaxException]
            throw new TaxException("Database access error ({$ex->getMessage()})", 30, $ex);
        }
        // construção do objeto [TaxAdminData]: os dados lidos são verificados
        $this->taxAdminData = TaxAdminData::fromArray([...$brackets, ...$constants]);
    }

    Este é o código da classe [DaoTaxWithTaxAdminDataInDatabase] da versão 5, apresentada no capítulo 13, sem a trait [TraitDao] que fornecia os métodos de leitura e escrita dos arquivos JSON dos contribuintes. Os métodos privados [getBrackets] e [getConstants] que vêm a seguir — não reproduzidos aqui — permanecem inalterados. Há apenas uma diferença:

    • linha 17: o atributo [taxAdminData] é declarado como [protected] em vez de [private]. A versão 9 derivará a classe [ServerDao], e a classe derivada precisa poder inicializar esse atributo. A partir do PHP 8.4, uma classe derivada pode inicializar um atributo [readonly] herdado, desde que ele não seja privado.

    <?php

// conformidade estrita com os tipos declarados dos parâmetros e resultados das funções
declare(strict_types=1);

// namespace
namespace Application;

// dependências do Symfony
use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;

// a pasta raiz do servidor: os caminhos do arquivo de configuração são relativos a esta pasta
const ROOT_DIRECTORY = __DIR__;
// caminho do arquivo de configuração
const CONFIG_FILENAME = ROOT_DIRECTORY . "/Data/config-server.json";

// recuperamos a configuração
$config = json_decode(file_get_contents(CONFIG_FILENAME), true, flags: JSON_THROW_ON_ERROR);

// incluímos as dependências necessárias ao script
require_once ROOT_DIRECTORY . "/../../../vendor/autoload.php";
foreach ($config["dependencies"] as $dependency) {
    require_once ROOT_DIRECTORY . "/$dependency";
}

// preparação da resposta JSON do servidor
$response = new JsonResponse();
// caracteres acentuados e / sem escape, floats sempre escritos com ponto decimal (0.0)
$response->setEncodingOptions(JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRESERVE_ZERO_FRACTION);

// recuperamos a requisição atual
$request = Request::createFromGlobals();
// autenticação: as credenciais enviadas pelo cliente (null se ele não enviou nenhuma)
$requestUser = $request->getUser();
$requestPassword = $request->getPassword();
// o usuário é um dos usuários autorizados?
$found = $requestUser !== null && $requestPassword !== null
    && array_any(
        $config["users"],
        fn(array $user): bool => $user["login"] === $requestUser && hash_equals($user["passwd"], $requestPassword)
    );
if (!$found) {
    // não encontrado - código 401
    $response->setStatusCode(Response::HTTP_UNAUTHORIZED);
    $response->headers->set("WWW-Authenticate", 'Basic realm="Tax calculation server"');
    // mensagem de erro
    $response->setData(["response" => ["error" => "Authentication failed [$requestUser]"]]);
    $response->send();
    // fim
    exit;
}

// temos um usuário válido - verificamos os parâmetros recebidos
$errors = [];
// devemos ter uma requisição GET com três parâmetros
if ($request->getMethod() !== "GET" || $request->query->count() !== 3) {
    $errors[] = "GET method required with only the parameters [married, children, salary]";
}
// o estado civil
if (!$request->query->has("married")) {
    $errors[] = "missing married parameter";
} else {
    $married = strtolower(trim($request->query->getString("married")));
    if (!in_array($married, ["yes", "no"], true)) {
        $errors[] = "invalid married parameter [$married]";
    }
}
// o número de filhos e o salário: inteiros >= 0
$values = [];
foreach (["children", "salary"] as $parameter) {
    if (!$request->query->has($parameter)) {
        $errors[] = "missing $parameter parameter";
        continue;
    }
    $value = trim($request->query->getString($parameter));
    if (preg_match('/^\d+$/', $value) !== 1) {
        $errors[] = "invalid $parameter parameter [$value]";
    } else {
        $values[$parameter] = (int) $value;
    }
}
// há outros parâmetros na requisição?
foreach (array_diff(array_keys($request->query->all()), ["married", "children", "salary"]) as $parameter) {
    $errors[] = "invalid parameter [$parameter]";
}
// erros?
if ($errors !== []) {
    // enviamos um código de erro 400 ao cliente
    $response->setStatusCode(Response::HTTP_BAD_REQUEST);
    $response->setData(["response" => ["errors" => $errors]]);
    $response->send();
    exit;
}

// temos tudo o que é preciso para trabalhar
// construção da arquitetura do servidor
try {
    // criação da camada [dao]
    $dao = new ServerDao(ROOT_DIRECTORY . "/" . $config["databaseFilename"]);
    // criação da camada [business]
    $business = new ServerBusiness($dao);
} catch (TaxException $ex) {
    // a mensagem de erro de um driver de SGBD pode não estar codificada em UTF-8 (Windows-1252 no Windows)
    $message = $ex->getMessage();
    if (!mb_check_encoding($message, "UTF-8")) {
        $message = mb_convert_encoding($message, "UTF-8", "Windows-1252");
    }
    // enviamos um código de erro 500 ao cliente
    $response->setStatusCode(Response::HTTP_INTERNAL_SERVER_ERROR);
    $response->setData(["response" => ["error" => $message]]);
    $response->send();
    exit;
}
// cálculo do imposto
$result = $business->calculateTax($married, $values["children"], $values["salary"]);
// retornamos a resposta
$response->setData(["response" => $result]);
$response->send();

    Comentários

    • linhas 10–12: são declaradas as classes da biblioteca [HttpFoundation] que serão usadas;
    • Linha 15: o diretório raiz do servidor é o diretório do script;
    • linha 20: o arquivo de configuração é carregado;
    • Linhas 23–26: carregamos o carregador de classes do [Composer] e, em seguida, todos os arquivos da aplicação;
    • linha 29: preparamos uma resposta JSON. A classe [JsonResponse] é uma subclasse de [Response]: seu método [setData] codifica em JSON o array que lhe é passado e o usa como corpo da resposta. Ele também define o cabeçalho HTTP [Content-Type: application/json];
    • Linha 31: as opções da função [json_encode], que é usada por [setData]. Com [JSON_UNESCAPED_UNICODE], os caracteres acentuados não são codificados em [\uXXXX]. Com [JSON_PRESERVE_ZERO_FRACTION], a alíquota efetiva [0.0] é escrita como [0.0] e não como [0]: o cliente a decodificará como um número de ponto flutuante (float) e não como um inteiro;
    • linhas 36–37: recuperamos os identificadores enviados pelo cliente, como no capítulo anterior;
    • linhas 39–43: verificamos se o usuário é de fato um dos usuários autorizados. A função [array_any] (PHP 8.4) retorna [true] se pelo menos um elemento do array [$config["users"]] satisfizer a condição expressa pela arrow function que lhe é passada. Ela substitui o laço [while] do script PHP 7. As senhas são comparadas com [hash_equals];
    • linhas 44–52: se não for o caso, o código HTTP [401 Unauthorized] é enviado, indicando que o acesso foi negado. Ao receber esse código e o cabeçalho HTTP [WWW-Authenticate: Basic realm=…], os navegadores exibem uma janela de autenticação pedindo ao usuário que se autentique;
    • Linha 49: a resposta JSON do servidor explica a causa do erro. Todas as respostas do servidor serão a string JSON de um array [["response" => something]]. O script PHP 7 devolvia ao cliente o nome de usuário e a senha rejeitados. Uma senha nunca deve ser devolvida nem gravada em logs: devolvemos apenas o nome de usuário;
    • Linhas 56–88: verificamos a validade da requisição:
      • uma requisição GET com exatamente três parâmetros;
      • um parâmetro [married] cujo valor deve ser [yes] ou [no];
      • um parâmetro [children], cujo valor deve ser um inteiro >= 0;
      • um parâmetro [salary], cujo valor deve ser um inteiro maior ou igual a 0;
      • nenhum outro parâmetro;
    • linha 59: cada vez que um erro é detectado, uma mensagem de erro é adicionada ao array [$errors];
    • linha 65: o método [getString] do objeto [$request->query] retorna o valor do parâmetro como uma string;
    • linha 72: os parâmetros [children] e [salary] seguem a mesma regra: são verificados no mesmo laço. Seus valores, convertidos em inteiros, são colocados no array [$values];
    • linha 85: a função [array_diff] retorna os nomes dos parâmetros recebidos que não estão na lista [married, children, salary];
    • linha 89: se ocorrer um erro, o código HTTP [400 Bad Request] é enviado ao cliente. A resposta JSON contém a lista de erros;
    • Linhas 99–104: a partir deste ponto, a requisição foi validada. As camadas [dao, business] podem ser instanciadas. Essa instanciação tem um custo (leitura do banco de dados) e só deve ser feita se você tiver certeza de que a requisição é válida. A construção da camada [dao] pode lançar uma exceção do tipo [TaxException];
    • linhas 106–108: a mensagem de erro costuma ser a do driver PDO do SGBD. No Windows, ela pode às vezes estar codificada em Windows-1252 em vez de UTF-8. No entanto, a função [json_encode] só aceita strings UTF-8: o [JsonResponse] lançaria então uma exceção. A função [mb_check_encoding] verifica a codificação da string, e a função [mb_convert_encoding] a converte, se necessário. O script PHP 7 usava a função [utf8_encode], que está obsoleta desde o PHP 8.2;

    18.2.4.1. Por que [http] e não [https]?

    O cliente envia suas credenciais: a rigor, a URL deveria ser segura ([https]), como vimos no capítulo anterior. Mas os navegadores modernos ([Chrome], [Edge], [Firefox]) só aceitam uma página HTTPS se o certificado do servidor for emitido por uma autoridade de certificação em que confiam. O certificado que o [Laragon] gera para [localhost] é autoassinado: ninguém o garante. Dependendo da versão do navegador e do estado de seu cache, o navegador exibe um aviso com um link ([Proceed to localhost (unsafe)]) ou se recusa a carregar a página sem oferecer a opção de prosseguir. Isso acontece quando o navegador registrou que [localhost] deve sempre ser servido com um certificado válido (mecanismo HSTS) ou quando considera o certificado não conforme. As soluções descritas no capítulo anterior (adicionar o certificado do [Laragon] ao repositório de certificados do [Windows], excluir a regra HSTS) nem sempre são suficientes.

    Por isso, usamos no navegador a URL não segura [http://localhost/...]. Isso não é uma falha de segurança aqui: uma requisição para [localhost] nunca sai da máquina (ela passa pela interface de rede interna, chamada interface de "loopback"), e nenhum software espião pode interceptá-la na rede. Aliás, os navegadores sabem disso: eles tratam [http://localhost] como uma origem confiável. Em contrapartida, assim que o servidor se torna acessível pela rede — e especialmente em ambiente de produção —, o protocolo HTTPS é indispensável, com um certificado válido emitido por uma autoridade reconhecida (por exemplo, gratuitamente, pelo [Let's Encrypt]).

    Os clientes que escrevemos, porém, não são navegadores: o comando [curl] (opção [-k]) e o cliente Symfony [HttpClient] (opções [verify_peer] definida como [false]) podem aceitar o certificado autoassinado do [Laragon]. No entanto, isso exige que o protocolo HTTPS tenha sido ativado no [Laragon] (menu [Apache / SSL / Enabled]), o que não é o caso por padrão, e que esse certificado possa ser usado na máquina. Para garantir que os exemplos funcionem em qualquer instalação do [Laragon], usaremos, portanto, URLs [http://localhost/...] ao longo deste capítulo e dos seguintes: no navegador, nos comandos [curl] e nos arquivos de configuração do cliente (chave [urlServer]). Para passar para HTTPS, basta substituir [http] por [https] nessas URLs e adicionar a opção [-k] aos comandos [curl]: os arquivos de configuração do cliente já contêm as opções necessárias [verify_peer] e [verify_host], que não têm efeito quando usadas com [http]. Os resultados são os mesmos com os dois esquemas.

// a camada [dao] do cliente: um cliente HTTP do servidor de cálculo de imposto
class ClientDao implements InterfaceClientDao
{
    // a trait da versão 5 implementa os métodos [getTaxPayersData] e [saveResults] da interface
    use TraitDao;

    // o cliente HTTP
    private readonly HttpClientInterface $httpClient;

    // construtor
    // $urlServer: a URL do servidor de cálculo de imposto
    // $user: o usuário que faz as requisições, array [login, passwd]
    // $httpClientOptions: opções adicionais do cliente HTTP (verify_peer, verify_host...)
    public function __construct(
        private readonly string $urlServer,
        #[\SensitiveParameter] array $user,
        array $httpClientOptions = [],
    ) {
        // o cliente HTTP: as credenciais do usuário serão enviadas a cada requisição
        $this->httpClient = HttpClient::create([
            ...$httpClientOptions,
            "auth_basic" => [$user["login"], $user["passwd"]],
        ]);
    }

    // cálculo do imposto pelo servidor
    #[\Override]
    public function calculateTax(string $married, int $children, int $salary): array
    {
        try {
            // fazemos a requisição ao servidor
            $response = $this->httpClient->request("GET", $this->urlServer, [
                "query" => [
                    "married" => $married,
                    "children" => $children,
                    "salary" => $salary,
                ],
            ]);
            // o status da resposta
            $statusCode = $response->getStatusCode();
            // o documento JSON da resposta, mesmo que o status seja um código de erro (parâmetro false)
            $json = $response->getContent(false);
        } catch (ExceptionInterface $ex) {
            // não foi possível alcançar o servidor
            throw new TaxException("Error communicating with the server ({$ex->getMessage()})", 40, $ex);
        }
        // logs
        // print "$json\n";
        // o servidor envia a string JSON de um array ["response" => algo]
        try {
            $serverResponse = json_decode($json, true, flags: JSON_THROW_ON_ERROR)["response"] ?? null;
        } catch (\JsonException $ex) {
            $serverResponse = null;
        }
        if (!is_array($serverResponse)) {
            throw new TaxException("Invalid server response [$json]", 41);
        }
        // erro?
        if ($statusCode !== 200) {
            // lançamos uma exceção cuja mensagem é a resposta do servidor completada com seu status HTTP
            $message = json_encode(
                ["HTTP status" => $statusCode] + $serverResponse,
                JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR
            );
            throw new TaxException($message, 42);
        }
        // retornamos a resposta: o array [tax, surcharge, discount, reduction, rate]
        return $serverResponse;
    }
}

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// a camada [business] do cliente: o cálculo do imposto é feito pelo servidor
class ClientBusiness implements InterfaceClientBusiness
{
    // a camada [dao] é injetada pelo construtor
    public function __construct(private readonly InterfaceClientDao $clientDao)
    {
    }

    // cálculo do imposto: ele é delegado à camada [dao], que consulta o servidor
    #[\Override]
    public function calculateTax(string $married, int $children, int $salary): array
    {
        return $this->clientDao->calculateTax($married, $children, $salary);
    }

    // cálculo dos impostos em modo batch
    #[\Override]
    public function executeBatchTaxes(string $taxPayersFileName, string $resultsFileName, string $errorsFileName): void
    {
        // deixamos subir as exceções vindas da camada [dao]
        // recuperamos os dados dos contribuintes
        $taxPayersData = $this->clientDao->getTaxPayersData($taxPayersFileName, $errorsFileName);
        // calculamos o imposto de cada contribuinte
        $results = array_map(
            fn(TaxPayerData $taxPayerData): TaxPayerData => $taxPayerData->withResults(
                $this->calculateTax($taxPayerData->married, $taxPayerData->children, $taxPayerData->salary)
            ),
            $taxPayersData
        );
        // salvamento dos resultados
        $this->clientDao->saveResults($resultsFileName, $results);
    }
}
