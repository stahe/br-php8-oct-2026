    11.2. Objetos trocados entre as camadas

    Mantemos certos elementos da versão 3 exatamente como estavam:

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// os dados de um contribuinte e os resultados do cálculo de seu imposto: um objeto imutável
final readonly class TaxPayerData
{
    public function __construct(
        // dados necessários para calcular o imposto do contribuinte
        public string $married,
        public int $children,
        public int $salary,
        // resultados do cálculo do imposto (null enquanto o imposto não tiver sido calculado)
        public ?int $tax = null,
        public ?int $surcharge = null,
        public ?int $discount = null,
        public ?int $reduction = null,
        public ?float $rate = null,
    ) {
    }

    // retorna uma cópia do objeto completada com os resultados do cálculo do imposto
    // $results: array [tax, surcharge, discount, reduction, rate] retornado pela camada [business]
    public function withResults(array $results): static
    {
        return clone($this, [
            "tax" => $results["tax"],
            "surcharge" => $results["surcharge"],
            "discount" => $results["discount"],
            "reduction" => $results["reduction"],
            "rate" => $results["rate"],
        ]);
    }

    // string JSON do objeto
    public function __toString(): string
    {
        return json_encode(get_object_vars($this), JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
    }
}

    Comentários

    • linha 9: assim como [TaxAdminData], a classe [TaxPayerData] é imutável: seus objetos passam de uma camada a outra sem risco de serem modificados no caminho;
    • Linhas 13–15: os dados do contribuinte necessários para calcular seu imposto;
    • Linhas 17–21: os resultados do cálculo do imposto. São campos anuláveis ([?int], [?float]) com o valor padrão [null]: um objeto [TaxPayerData] é criado primeiro pela camada [dao] contendo apenas os dados do contribuinte, a partir de [new TaxPayerData("yes", 2, 55555)], já que o imposto ainda não foi calculado. Os nomes dos atributos são os das chaves JSON do arquivo de resultados da versão 3: o arquivo [results.txt] manterá, assim, o mesmo formato;
    • Linhas 27–36: como o objeto é imutável, os resultados do cálculo não podem ser adicionados a ele. O método [withResults] retorna uma cópia do objeto complementada com os resultados. Ele usa o operador [clone] do PHP 8.5, que aceita como segundo parâmetro um array de atributos a serem modificados na cópia (veja o capítulo sobre classes). O curso de PHP 7 usava um objeto modificável com oito getters e oito setters;
    • linhas 39–42: o método [__toString] retorna a string JSON do objeto. Ele será usado para escrever o arquivo de resultados.

    Comentários

    • As especificações são as seguintes:
      • Os dados dos contribuintes são armazenados em um arquivo de texto;
      • os resultados do cálculo do imposto são gravados em um arquivo de texto;
      • Os eventuais erros são gravados em um arquivo de texto;
      • não se sabe em que formato os dados da administração tributária estão disponíveis. Para cada novo formato, a interface [InterfaceDao] deverá ser implementada por uma nova classe;
      • os métodos da interface que encontrarem um erro fatal ao acessar os dados devem lançar uma exceção [TaxException];
    • Linha 15: o método que recupera os dados dos contribuintes [marital status, number of children, annual salary]:
      • o primeiro parâmetro é o nome do arquivo de texto que contém esses dados;
      • o segundo parâmetro é o nome do arquivo de texto no qual devem ser registrados os eventuais erros encontrados;
    • Linha 14: o tipo [array] não especifica o que o array contém. O comentário de documentação [/** @return TaxPayerData[] */] (sintaxe PHPDoc) especifica que se trata de um array de objetos [TaxPayerData]. O PHP ignora isso, mas a extensão [PHP Intelephense] do [VS Code] o utiliza: ela passa a conhecer o tipo dos elementos do array e pode sugerir seus atributos durante a digitação;
    • linha 18: o método que recupera os dados da administração tributária. Nenhum parâmetro lhe é passado porque não sabemos como os dados são armazenados;
    • linha 22: o método que grava os resultados do cálculo do imposto em um arquivo de texto, cujo nome é passado como parâmetro.

    Ao escrever a interface [InterfaceDao], sabemos que haverá diferentes maneiras de implementar o método [getTaxAdminData], conforme o modo como os dados da administração tributária estão armazenados. A interface [InterfaceDao] será, portanto, implementada por diferentes classes, cada uma tratando de uma forma específica de armazenamento desses dados (arquivo JSON, banco de dados, serviço web). Essas classes compartilharão, porém, código comum: a implementação dos métodos [getTaxPayersData] e [saveResults]. Como vimos no capítulo sobre traits, esse caso de uso pode ser implementado de duas maneiras:

    • Cria-se uma classe abstrata C que contém o código comum às classes derivadas. A classe C implementa a interface I, mas certos métodos — que devem ser definidos nas classes derivadas — são declarados abstratos na classe C, que portanto é ela própria abstrata. Criam-se então as classes C1 e C2 derivadas de C, cada uma implementando à sua maneira os métodos abstratos de sua classe-mãe C;
    • cria-se um trait T quase idêntico à classe abstrata C da solução anterior. Esse trait não implementa a interface I porque, sintaticamente, não pode. Criam-se então as classes C1 e C2, que implementam a interface I e usam o trait T. Resta a essas classes apenas implementar os métodos da interface I que não são implementados pelo trait T que elas importam.

    Neste exemplo, usaremos um trait [TraitDao]. A versão 3 usava uma classe abstrata.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// implementação dos métodos de [InterfaceDao] que trabalham com arquivos de texto
trait TraitDao
{
    // separador dos campos de uma linha do arquivo de contribuintes (constante de trait, PHP 8.2)
    private const string SEPARATOR = ",";

    // leitura dos dados dos contribuintes
    #[\Override]
    public function getTaxPayersData(string $taxPayersFilename, string $errorsFilename): array
    {
        // array dos dados dos contribuintes
        $taxPayersData = [];
        // array dos erros
        $errors = [];
        // abertura do arquivo de dados dos contribuintes
        $taxPayersFile = is_readable($taxPayersFilename) ? fopen($taxPayersFilename, "r") : false;
        if ($taxPayersFile === false) {
            throw new TaxException("Unable to open the taxpayers' declarations [$taxPayersFilename] for reading", 12);
        }
        // o arquivo está aberto: teremos de fechá-lo aconteça o que acontecer
        try {
            // processamos a linha atual do arquivo de dados dos contribuintes
            // que tem o formato estado civil, número de filhos, salário anual
            $num = 0;  // nº da linha atual
            while (($line = fgets($taxPayersFile, 100)) !== false) {
                // mais uma linha
                $num++;
                // removemos a possível marca de fim de linha
                $line = Utilities::cutNewLineChar($line);
                // ignoramos as linhas vazias
                if (trim($line) === "") {
                    continue;
                }
                // a linha deve ter 3 campos married,children,salary
                $fields = array_map(trim(...), explode(self::SEPARATOR, $line));
                $error = count($fields) !== 3;
                if (!$error) {
                    [$married, $children, $salary] = $fields;
                    // o estado civil deve ser yes ou no
                    $married = strtolower($married);
                    // o número de filhos e o salário devem ser inteiros positivos ou zero
                    $error = !in_array($married, ["yes", "no"], true)
                        || !preg_match('/^\d+$/', $children)
                        || !preg_match('/^\d+$/', $salary);
                }
                // erro?
                if ($error) {
                    $errors[] = "line [$num] of the file [$taxPayersFilename] is incorrect";
                } else {
                    // armazenamos os dados do contribuinte
                    $taxPayersData[] = new TaxPayerData($married, (int) $children, (int) $salary);
                }
            }
            // chegamos ao fim do arquivo?
            if (!feof($taxPayersFile)) {
                // saímos do laço por causa de um erro de leitura
                throw new TaxException("Error while reading the line no. [" . ($num + 1) . "] of the file [$taxPayersFilename]", 13);
            }
        } finally {
            // fechamos o arquivo
            fclose($taxPayersFile);
        }
        // salvamos os erros em um arquivo de texto
        $this->saveLines($errorsFilename, $errors);
        // resultado da função
        return $taxPayersData;
    }

    // salvamento dos resultados
    #[\Override]
    public function saveResults(string $resultsFilename, array $taxPayersData): void
    {
        // cada elemento [TaxPayerData] é transformado em string JSON por seu método [__toString]
        $this->saveLines($resultsFilename, array_map(strval(...), $taxPayersData));
    }

    // salvamento de um array de linhas em um arquivo de texto
    private function saveLines(string $fileName, array $lines): void
    {
        // se o arquivo de texto [$fileName] não existir, ele é criado; caso contrário, é sobrescrito
        $data = implode("", array_map(fn(string $line): string => "$line\n", $lines));
        if (@file_put_contents($fileName, $data) === false) {
            throw new TaxException("Error while saving data to the text file [$fileName]", 14);
        }
    }
}

    Comentários

    • Linha 9: aqui estamos definindo um trait, não uma classe;
    • Linha 12: uma constante de separador de campos (PHP 8.2), tipada (PHP 8.3): o separador de campos de uma linha do arquivo de contribuintes. Ela se torna uma constante da classe que usa o trait e é usada com a notação [self::SEPARATOR];
    • Linha 15: a partir do PHP 8.3, o atributo [#[\Override]] é aceito em um método de trait. Isso é verificado na classe que usa o trait: aqui, o método deve corresponder a um método da interface [InterfaceDao] implementada por essa classe;
    • Linhas 16–74: o método [getTaxPayersData] implementa o método de mesmo nome da interface [InterfaceDao]. Ele recupera os dados dos contribuintes [marital status, number of children, annual salary] do arquivo de texto de nome [$taxPayersFilename]. Retorna esses dados na forma de um array [$taxPayersData] contendo elementos do tipo [TaxPayerData] (linha 58);
    • O método [getTaxPayersData] é muito semelhante ao método [AbstractBaseTax::executeBatchTaxes] da versão 3, com as seguintes diferenças:
      • O método [getTaxPayersData] apenas recupera os dados dos contribuintes. Ele não realiza nenhum cálculo de imposto: esse é o papel da camada [business];
      • Assim como o método [executeBatchTaxes], ele sinaliza as linhas errôneas. Aqui, os erros são primeiro armazenados em um array chamado [$errors], que é gravado em um arquivo de texto ao final do processamento (linha 71). Dependendo da situação, esse array pode estar vazio ou não. Uma linha errônea não dispara mais uma exceção: cabe ao código chamador consultar o arquivo de erros;
      • em caso de erro fatal, uma exceção [TaxException] é lançada (linha 25, linha 64);
    • Linhas 23–26: o arquivo é aberto antes da estrutura [try / finally]. Se a abertura do arquivo falhar, uma exceção é lançada e não há nada a fechar. Se ela der certo, a cláusula [finally] (linhas 66–69) garante que o arquivo seja fechado, ocorra ou não uma exceção. Essa abordagem evita a verificação “O arquivo foi aberto?” presente na versão 3;
    • Linhas 62–65: observe o tratamento realizado na saída do laço de leitura. A função [fgets] tem o inconveniente de retornar [false] tanto quando a leitura chega ao fim do arquivo quanto quando falha por causa de um erro. Para distinguir os dois casos, verificamos se chegamos ao fim do arquivo usando a função [feof]. Se não for o caso, ocorreu um erro, e uma exceção é então lançada;
    • linhas 78–82: implementação do método [saveResults] da interface [InterfaceDao]. Cada elemento [TaxPayerData]do array é convertido em string pela função [strval], que chama o método [__toString] do objeto: isso resulta em sua string JSON. [strval(...)] refere-se à própria função [strval] (first-class callable, PHP 8.1);
    • linhas 85–92: o método privado [saveLines] grava um array de linhas em um arquivo de texto, com cada linha terminada pelo caractere de fim de linha \n;
    • linha 89: a função PHP [file_put_contents] grava uma string em um arquivo de texto. Ela abre o arquivo, grava a string nele e fecha o arquivo. Retorna [false] se ocorrer um erro. Nesse caso, o PHP também emite um aviso. O operador [@]suprime esse aviso: o erro é informado pela exceção lançada na linha seguinte, com uma mensagem mais clara.

    O trait [TraitDao] implementou dois dos métodos da interface [InterfaceDao]: [getTaxPayersData] e [saveResults]. Ainda falta implementar o método [getTaxAdminData], que recupera os dados da administração tributária.

        if ($tax1 > $tax2) {

            $rate = $result1["rate"];
            $surcharge = $result1["surcharge"];

            $surcharge = $tax2 - $tax1 + $result2["surcharge"];
            $tax = $tax2;
            $rate = $result2["rate"];

        $discount = $this->getDiscount($married, $salary, $tax);
        $tax -= $discount;
        // cálculo de uma possível redução de imposto
        $reduction = $this->getReduction($married, $salary, $children, $tax);
        $tax -= $reduction;
        // resultado
        return [

    • linha 7: as classes de teste estão no namespace [Application\Tests], distinto do da aplicação;
    • Linhas 10–16: as classes usadas são importadas com a instrução [use]. As classes da aplicação estão no namespace [Application], e as do PHPUnit estão em [PHPUnit\Framework];
    • Linhas 19–25: carregam os arquivos da camada [dao], como em [main.php]. Os caminhos são relativos à pasta do arquivo de teste ([__DIR__]): os testes são executados independentemente da pasta a partir da qual o PHPUnit é iniciado e independentemente da localização da pasta [php8-oct-2026] no disco. O curso de PHP 7 usava caminhos absolutos ([C:/Data/...]) específicos da máquina do autor. As classes do PHPUnit, por sua vez, são carregadas automaticamente pelo carregador do [Composer], que é inicializado pelo PHPUnit;
    • linha 27: a classe de teste estende [TestCase];
    • linha 30: a pasta da versão 4, onde estão os arquivos de dados;
    • Linhas 38–44: antes de cada teste, a camada [dao] é construída como faz o [main.php], e um arquivo temporário é criado para os erros. A função [tempnam] cria um arquivo de nome único na pasta de arquivos temporários do sistema, retornada por [sys_get_temp_dir]. O curso de PHP 7 realizava essa tarefa no construtor da classe de teste: o construtor de [TestCase] não precisa mais ser redefinido a partir do PHPUnit 10;
    • linhas 48–52: após cada teste, o arquivo temporário é excluído;
    • linhas 55–73: teste dos dados da administração tributária. Verificamos que o conteúdo do objeto [TaxAdminData] retornado pela camada [dao] corresponde ao esperado. O método [assertSame] é usado: [assertSame(1551.0, ...)] verifica que o valor é o número real 1551.0; [assertSame(1551, ...)] falharia, pois o inteiro 1551 não é idêntico ao número real 1551.0. Para arrays, [assertSame] verifica que os dois arrays têm as mesmas chaves, na mesma ordem, com valores idênticos;
    • linhas 76–85: um provedor de dados (data provider). É um método público estático que retorna um array de conjuntos de dados. Cada conjunto é um array de argumentos a serem passados a um método de teste. A chave de cada conjunto (“arquivo inexistente”...) dá a ele um nome que aparecerá nos resultados dos testes;
    • linha 87: o atributo do PHP 8 [#[DataProvider]] indica que o método de teste [testInvalidTaxAdminData] deve ser executado uma vez para cada conjunto de dados do provedor [invalidFiles]. As versões do PHPUnit anteriores à 10 usavam, em vez disso, uma anotação em comentário: as anotações não são mais reconhecidas a partir do PHPUnit 12;
    • Linhas 88–95: verificam que uma camada construída com um arquivo de dados tributários incorreto lança uma exceção com o código de erro correto. Os métodos [expectException] e [expectExceptionCode] devem ser chamados antes do código que lança a exceção: o teste passa se a exceção for lançada; caso contrário, falha. Os arquivos incorretos estão na pasta [Tests/data]: um arquivo JSON malformado (vírgula ausente), um arquivo sem a chave [coupleDiscountCeiling] e um arquivo com um valor negativo;
    • Linhas 98–112: o teste da leitura dos dados dos contribuintes. O arquivo [taxpayersdata.txt] da versão 4 contém 11 linhas corretas e 2 linhas errôneas. Verificamos o número de contribuintes recuperados, seu tipo ([assertContainsOnlyInstancesOf]), o conteúdo do primeiro e do último registro e, em seguida, o conteúdo do arquivo de erros. Para comparar dois objetos [TaxPayerData], usamos [assertEquals]: dois objetos distintos nunca são idênticos ([===]), mas são iguais ([==]) se seus atributos forem iguais;
    • Linhas 115–120: um arquivo de contribuintes inexistente deve disparar uma exceção de código 12.
