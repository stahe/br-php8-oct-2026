    9. Traits

    Traits são estruturas análogas a classes. No entanto, elas não podem ser instanciadas: destinam-se a ser incluídas em classes. Incluir um trait em uma classe tem o mesmo efeito que se o código do trait tivesse sido copiado para a classe. O código que pode ser reutilizado em várias classes é colocado em um trait.

    Os traits existem desde o PHP 5.4. O PHP 8 introduziu várias novidades, que discutiremos no final deste capítulo: verificação de assinatura para métodos abstratos (PHP 8.0), constantes em traits (PHP 8.2), o atributo [#[\Override]] utilizável em um trait (PHP 8.3).

    <?php

declare(strict_types=1);

class Class04
{
    // construtor com promoção do atributo [name]
    public function __construct(private string $name)
    {
    }

    // getter e setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

trait Trait04
{
    // atributo
    private string $name;

    // getter e setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

class Class05
{
    // inclusão do trait
    use Trait04;

    // construtor
    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

// teste --------------
$class04 = new Class04("Tim");
$class05 = new Class05("Burton");
print $class04->getName() . "\n";
print $class05->getName() . "\n";
// exibição dos dois objetos
print_r($class04);
print_r($class05);

    Comentários sobre o código

    • linhas 5–22: definição da classe [Class04] com um atributo [$name] (inicializado pelo construtor), seu getter e seu setter;
    • linhas 24–39: pegamos o código de [Class04]—excluindo seu construtor—e o movemos para o trait [Trait04]. Desta vez, o atributo é declarado explicitamente, juntamente com seu tipo. Não incluímos o construtor, pois um trait não pode ser instanciado;
    • linha 24: a palavra-chave [trait] designa [Trait04] como um trait em vez de uma classe;
    • linhas 41–51: definimos uma classe [Class05] que inclui o código do trait [Trait04] e lhe acrescenta um construtor, para tornar a classe instanciável;
    • Linha 44: a palavra-chave [use], colocada dentro de uma classe, permite incluir um trait na classe. Ela não deve ser confundida com a instrução [use], que é colocada fora de qualquer classe e importa um nome de um namespace;
    • Linhas 54–60: os testes mostram que as classes [Class04] e [Class05] funcionam da mesma maneira.

    <?php

declare(strict_types=1);

trait Trait01
{
    // atributo
    private int $id = 0;

    // método
    public function doSomething(): void
    {
        print "Trait01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // inclusão de Trait01
    use Trait01 {
        // o método [Trait01::doSomething] é acessível
        // na classe com o nome [doSomethingInTrait]
        Trait01::doSomething as doSomethingInTrait;
    }

    // método específico da classe
    public function doSomething(): void
    {
        // atributo id
        $this->id += 10;
        // uso do método de Trait01
        $this->doSomethingInTrait();
        // exibição local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // inclusão de Trait01
    use Trait01;

    // método local da classe
    public function doSomethingElse(): void
    {
        // atributo id
        $this->id += 10;
        // uso do método de Trait01
        $this->doSomething();
        // exibição local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    $class02 = new Class02();
    $class03 = new Class03();
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();

    Comentários

    • linhas 5–15: um trait que define um atributo [$id] e um método [doSomething];
    • o trait [Trait01] é incluído em duas classes: [Class02] (linhas 17–36) e [Class03] (linhas 38–53);
    • linhas 20–24: inclusão de [Trait01] em [Class02]. A inclusão é seguida por um bloco [{...}] que permite ajustar os métodos incluídos;
    • linha 23: essa linha resolve um conflito: [Trait01] e [Class02] possuem ambas um método chamado [doSomething]. Nesse caso, o método da classe tem precedência: o método do trait fica oculto. O operador [as] torna o método [Trait01::doSomething] acessível na classe com o nome [doSomethingInTrait]. Assim, dentro de [Class02], usaremos as seguintes notações:
      • [doSomethingInTrait] para chamar o método [Trait01::doSomething];
      • [doSomething] para chamar o método [Class02::doSomething];
    • Linhas 30–32: a classe [Class02] usa o atributo e o método de [Trait01] como se fossem seus;
    • linhas 38–53: a classe [Class03] é análoga à classe [Class02]. A inclusão de [Trait01] é mais simples aqui porque não há conflito entre os métodos de [Trait01] e de [Class03].

    <?php

declare(strict_types=1);

// classe que substitui o trait
class Class01
{
    // atributo
    private int $id = 0;

    // setter
    public function setId(int $id): void
    {
        $this->id = $id;
    }

    // getter
    public function getId(): int
    {
        return $this->id;
    }

    // método
    public function doSomething(): void
    {
        print "Class01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // uma referência a uma instância de Class01, injetada pelo construtor
    public function __construct(private readonly Class01 $class01)
    {
    }

    // método específico da classe
    public function doSomething(): void
    {
        // modificação do atributo de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // uso do método de Class01
        $this->class01->doSomething();
        // exibição local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // uma referência a uma instância de Class01, injetada pelo construtor
    public function __construct(private readonly Class01 $class01)
    {
    }

    // método local da classe
    public function doSomethingElse(): void
    {
        // modificação do atributo de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // uso do método de Class01
        $this->class01->doSomething();
        // exibição local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ----------------
function test01(): void
{
    // dois objetos que acessarão duas instâncias diferentes de [Class01]
    $class02 = new Class02(new Class01());
    $class03 = new Class03(new Class01());
    // verificação
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test02 ----------------
function test02(): void
{
    // instância compartilhada de [Class01]
    $class01 = new Class01();
    // dois objetos que acessarão a mesma instância de [Class01]
    $class02 = new Class02($class01);
    $class03 = new Class03($class01);
    // verificação
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();
// test02
print "test02-----------------\n";
test02();

    Comentários

    • Linhas 6–28: a classe [Class01] substitui o trait [Trait01]. O código de [Trait01] foi incorporado ao código das classes [Class02] e [Class03]. Aqui, não será assim: uma referência a um objeto [Class01] será injetada nas classes [Class02] e [Class03] . Os atributos da classe [Class01] serão, portanto, externos aos objetos [Class02] e [Class03] . Como o atributo [$id] é privado, é preciso fornecer um getter e um setter. Essa é a primeira diferença em relação a um trait: é preciso criar código para acessar os atributos privados da classe. Poderíamos ter tornado o atributo [$id] público, mas isso não é recomendado: usar um setter para definir o valor de um atributo permite validá-lo;
    • Linha 33: a referência ao objeto *[Class01] é injetada em *[Class02] por seu construtor, graças à promoção de parâmetros. O curso de PHP 7 usava um setter [setClass01]. A injeção pelo construtor é preferível: o objeto [Class02] está completo assim que é construído e, como o atributo é [readonly], a referência não pode mais ser alterada;
    • linhas 41–45: para qualquer uso do código de [Class01], precisamos passar pelo atributo [$this->class01];
    • linhas 51–70: a classe [Class03] é um clone da classe [Class02], exceto que seu método tem um nome diferente;
    • linhas 73–81: o primeiro teste. Consiste em injetar duas instâncias diferentes da classe [Class01] nos objetos [Class02] e [Class03];
    • linhas 84–94: o segundo teste injeta a mesma instância da classe [Class01] nos objetos [Class02] e [Class03].

    9.4. Agrupando métodos em um trait

    No exemplo anterior, o trait continha atributos e métodos. Aqui, vamos considerar o caso em que ele contém apenas métodos. O trait passa então a ser uma fatoração de métodos que podem ser usados em classes diferentes. Como o trait aqui não tem atributos, vamos considerar o caso em que os métodos que ele contém operam exclusivamente sobre os parâmetros recebidos. Isso não é obrigatório: um trait pode operar sobre um atributo [$this->attribute1] sem possuir esse atributo. Nesse caso, cabe às classes que usam o trait fornecer o atributo [$this->attribute1].

    No caso em que o trait tem apenas métodos que operam exclusivamente sobre os parâmetros recebidos, mostraremos que o trait pode ser substituído por uma classe com os mesmos métodos do trait, declarados como estáticos.

Veremos no final do capítulo que o PHP 8 oferece uma solução limpa para exigir algo das classes que usam um trait: os métodos abstratos.

    9.5. Herança múltipla com um trait

declare(strict_types=1);

trait Trait01
{
    // atributo
    private int $i = 0;

    // método a ser compartilhado
    public function doSomethingInTrait01(): void
    {
        // modificação de Trait01::$i
        $this->i++;
        // exibição
        print "Trait01::doSomethingInTrait01... i=$this->i\n";
    }
}

class Class02
{
    // atributo acessível às classes derivadas
    protected int $j = 0;

    // método
    public function doSomethingInClass02(): void
    {
        // modificação de Class02::$j
        $this->j += 10;
        // exibição
        print "Class02->doSomethingInClass02... j=$this->j\n";
    }
}

// classe derivada
class Class03 extends Class02
{
    // herda Class02::$j e inclui Trait01::$i
    use Trait01;

    // método
    public function doSomethingInClass03(): void
    {
        // uso do método de Trait01
        $this->doSomethingInTrait01();
        // modificação de Trait01::$i
        $this->i += 100;

    9.6. Usando um trait em vez de uma classe abstrata

    O caso de uso a seguir é comum: cria-se uma interface I bastante geral, que pode dar origem a várias implementações. Essas implementações compartilham código comum, mas diferem em outros métodos. Há duas maneiras de implementar esse caso de uso:

    • Cria-se uma classe abstrata C que contém o código comum às classes derivadas. A classe C implementa a interface I, mas certos métodos — que devem ser definidos nas classes derivadas — são declarados abstratos na classe C, que portanto é ela própria abstrata. Criam-se então as classes C1 e C2 derivadas de C, cada uma implementando à sua maneira os métodos abstratos de sua classe-mãe C;
    • cria-se um trait T quase idêntico à classe abstrata C da solução anterior. Esse trait não implementa a interface I porque, sintaticamente, não pode. Criam-se então as classes C1 e C2, que implementam a interface I e usam o trait T. Resta a essas classes apenas implementar os métodos da interface I que não são implementados pelo trait T que elas importam.

    <?php

declare(strict_types=1);

interface Interface1
{
    public function doSomething(): void;

    public function doSomethingElse(): void;
}

abstract class AbstractClass implements Interface1
{
    // atributos acessíveis às classes derivadas
    protected int $attr1 = 11;
    protected int $attr2 = 12;

    // getters e setters
    public function getAttr1(): int
    {
        return $this->attr1;
    }

    public function getAttr2(): int
    {
        return $this->attr2;
    }

    public function setAttr1(int $attr1): static
    {
        $this->attr1 = $attr1;
        return $this;
    }

    public function setAttr2(int $attr2): static
    {
        $this->attr2 = $attr2;
        return $this;
    }

    // método implementado
    #[\Override]
    public function doSomething(): void
    {
        print "AbstractClass::doSomething [$this->attr1,$this->attr2]\n";
    }

    // método não implementado
    #[\Override]
    abstract public function doSomethingElse(): void;
}

// classe derivada 1
class Class1 extends AbstractClass
{
    // atributo
    private int $attr3 = 13;

    // getter e setter
    public function getAttr3(): int
    {
        return $this->attr3;
    }

    public function setAttr3(int $attr3): static
    {
        $this->attr3 = $attr3;
        return $this;
    }

    // implementação de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class1::doSomethingElse [$this->attr1,$this->attr2,$this->attr3]\n";
    }
}

// classe derivada 2
class Class2 extends AbstractClass
{
    // atributo
    private int $attr4 = 14;

    // getter e setter
    public function getAttr4(): int
    {
        return $this->attr4;
    }

    public function setAttr4(int $attr4): static
    {
        $this->attr4 = $attr4;
        return $this;
    }

    // implementação de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class2::doSomethingElse [$this->attr1,$this->attr2,$this->attr4]\n";
    }
}

// função externa
function useInterfaceWith(Interface1 $interface): void
{
    $interface->doSomething();
    $interface->doSomethingElse();
}

// testes
useInterfaceWith(new Class1());
useInterfaceWith(new Class2());
// setters "fluentes" podem ser encadeados
useInterfaceWith((new Class1())->setAttr1(21)->setAttr2(22)->setAttr3(23));

    Comentários

    • linhas 5–10: a interface [Interface1] tem dois métodos;
    • linha 12: a classe abstrata [AbstractClass] implementa a interface [Interface1]. Ela tem dois atributos com seus getters e setters, implementa o método [doSomething] da interface [Interface1] (linha 43), mas não implementa o método [doSomethingElse]. Esse método é, portanto, declarado abstrato (linha 50). A classe abstrata [AbstractClass] não pode ser instanciada e, para ser útil, precisa ser derivada;
    • Linhas 29–39: os setters são “fluentes”: em vez de não retornar nada, eles retornam o objeto [$this]. Isso permite chamadas encadeadas (linha 116). O tipo de retorno [static] (PHP 8.0) refere-se à classe do objeto sobre o qual o método foi chamado: [(new Class1())->setAttr1(21)] é do tipo [Class1] e não [AbstractClass], o que permite chamar em seguida [setAttr3]— um método específico de [Class1];
    • Linha 54: a classe [Class1] estende a classe abstrata [AbstractClass] e, portanto, implementa a interface [Interface1]. Ela fornece um corpo para o método [doSomethingElse], que sua classe-mãe não havia definido. Ela também acrescenta um atributo aos de sua classe-mãe;
    • Linha 80: a classe [Class2] faz o mesmo com outro atributo;
    • linhas 106–110: a função [useInterfaceWith] recebe como parâmetro um tipo [Interface1] e chama os dois métodos dessa interface;
    • Linhas 113–116: a função [useInterfaceWith] é chamada com um tipo [Class1] e depois com um tipo [Class2]. Isso é correto porque ambos os tipos implementam a interface [Interface1].

    <?php

declare(strict_types=1);

// um trait que exige algo das classes que o usam
trait CounterTrait
{
    // constante de trait (PHP 8.2)
    public const int STEP = 10;

    // atributo estático: cada classe que o usa tem o seu
    private static int $nbInstances = 0;

    // atributo de instância
    private int $counter = 0;

    // método estático do trait
    public static function getNbInstances(): int
    {
        return self::$nbInstances;
    }

    // método abstrato: a classe que o usa deve defini-lo (assinatura verificada desde o PHP 8.0)
    abstract protected function getName(): string;

    // a ser chamado pelo construtor da classe que usa o trait
    private function register(): void
    {
        self::$nbInstances++;
    }

    // método concreto que usa o método abstrato e a constante
    public function increment(): static
    {
        $this->counter += self::STEP;
        print "{$this->getName()}: counter=$this->counter\n";
        return $this;
    }
}

class Car
{
    use CounterTrait;

    public function __construct(private string $registration)
    {
        $this->register();
    }

    // implementação do método abstrato do trait
    #[\Override]
    protected function getName(): string
    {
        return "Car[$this->registration]";
    }
}

class Bike
{
    use CounterTrait;

    public function __construct()
    {
        $this->register();
    }

    #[\Override]
    protected function getName(): string
    {
        return "Bike";
    }
}

// testes
(new Car("AB-123-CD"))->increment()->increment();
new Car("EF-456-GH");
(new Bike())->increment();
// cada classe tem seu próprio atributo estático
print "number of cars: " . Car::getNbInstances() . "\n";
print "number of bikes: " . Bike::getNbInstances() . "\n";
// a constante do trait é acessível pela classe, não pelo trait
print "step: " . Car::STEP . "\n";
try {
    print CounterTrait::STEP . "\n";
} catch (\Error $ex) {
    print $ex::class . ": " . $ex->getMessage() . "\n";
}
// uma classe que usa o trait deve implementar o método abstrato
// class Plane { use CounterTrait; }  // Fatal error: Class Plane contains 1 abstract method...

    Comentários

    • linha 9: desde o PHP 8.2, um trait pode declarar constantes. Elas se tornam constantes da classe que usa o trait;
    • linha 12: um trait pode declarar atributos estáticos. Assim como os atributos de instância, eles são copiados para cada classe que usa o trait: cada classe tem seu próprio contador de instâncias;
    • Linhas 18–21: um trait pode declarar métodos estáticos. No código do trait, [self] refere-se à classe que usa o trait;
    • Linha 24: um trait pode declarar métodos abstratos. Toda classe que usa o trait deve implementá-los; caso contrário, ela própria deve ser declarada abstrata (veja a classe [Plane] comentada no final do script). A partir do PHP 8.0, a assinatura da implementação (tipos dos parâmetros e do retorno) é verificada. Essa é a maneira correta de impor requisitos às classes que usam o trait, em vez de supor que elas tenham um determinado atributo ou método;
    • Linhas 33–38: um método concreto [increment] que usa o método abstrato [getName] e a constante [STEP]. Ele retorna [$this] (tipo [static]) para que possa ser encadeado;
    • Linhas 41–56: a classe [Car] usa o trait, chama em seu construtor o método privado [register] do trait e implementa o método abstrato [getName]. Observe o atributo [#[\Override]] nessa implementação: ele é aceito porque a classe implementa um método abstrato do trait;
    • linhas 58–72: a classe *[Bike]* faz o mesmo;
    • linhas 79–80: cada classe tem seu próprio atributo estático [$nbInstances];
    • linha 82: a constante do trait é acessível por meio da classe que o usa;
    • linha 84: mas não diretamente por meio do trait: ocorre um erro.

    9.8. Conclusão

    Pelos exemplos anteriores, fica claro que os casos de uso em que o trait traz um benefício líquido não são evidentes. Em nossos exemplos, sempre podemos dispensá-lo substituindo-o por uma classe. No entanto, ele é útil para fatorar código entre classes diferentes, como se esse código pertencesse a uma classe-mãe, sem consumir a herança simples de que dispõe uma classe PHP. É o que faremos na versão 4 do exercício de aplicação.
