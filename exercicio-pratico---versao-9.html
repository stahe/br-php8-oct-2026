    19. Exercício prático – Versão 9

    Nesta versão, melhoraremos o servidor da seguinte forma:

    • Atualmente, a cada requisição, os dados da administração tributária são obtidos do banco de dados. Usaremos uma sessão:
      • quando um usuário faz sua primeira requisição, os dados da administração tributária são obtidos do banco de dados e armazenados na sessão;
      • nas requisições seguintes do mesmo usuário, os dados da administração tributária são obtidos da sessão. Podemos esperar uma ligeira melhoria no tempo de execução, já que as consultas ao banco de dados são custosas;
    • a sessão também garantirá que o usuário seja autenticado apenas uma vez;
    • O servidor registrará os eventos importantes em um arquivo de texto (logs):
      • autenticação bem-sucedida ou malsucedida;
      • se os parâmetros enviados pelo cliente são válidos;
      • o resultado do cálculo do imposto;
      • diversos casos de erro;
    • em caso de erro fatal, um e-mail será enviado ao administrador da aplicação.

    O cliente também precisará ser modificado para tratar o cookie de sessão que o servidor lhe enviará.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// um log em um arquivo de texto
final readonly class Logger
{
    // construtor: o arquivo de log é criado se não existir
    public function __construct(private string $logsFilename)
    {
        // verificamos que podemos escrever no arquivo (anexando uma string vazia)
        if (@file_put_contents($logsFilename, "", FILE_APPEND) === false) {
            throw new TaxException("Failed to create the log file [$logsFilename]", 50);
        }
    }

    // escrita de uma mensagem nos logs, precedida da data e da hora
    public function write(string $message): void
    {
        $date = (new \DateTimeImmutable())->format("d/m/y H:i:s.v");
        // FILE_APPEND: escrevemos no fim do arquivo
        // LOCK_EX: o arquivo é bloqueado durante a escrita
        file_put_contents($this->logsFilename, "$date : $message\n", FILE_APPEND | LOCK_EX);
    }
}

    Comentários

    • Linha 9: A classe é [final] (não pode ser estendida) e [readonly]: seu único atributo, o nome do arquivo de log, não pode ser modificado após a criação do objeto;
    • linha 12: O construtor da classe recebe o nome do arquivo de log como parâmetro;
    • linha 15: Verificamos se é possível gravar no arquivo acrescentando-lhe uma string vazia. O flag [FILE_APPEND] garante que o arquivo seja criado se não existir e que seu conteúdo seja preservado caso contrário. O operador [@] impede que o PHP exiba um aviso em caso de falha: tratamos o erro nós mesmos;
    • linha 16: se a gravação falhou, uma exceção é lançada;
    • linha 21: o método [write] grava a mensagem [$message] no arquivo de log, precedida da data e da hora. O formato [d/m/y H:i:s.v] especifica o dia, o mês e o ano (com dois dígitos), seguidos das horas, minutos, segundos e milissegundos;
    • Linha 26: A função [file_put_contents] abre o arquivo, acrescenta a linha e o fecha. Portanto, não há mais um método [close] como na versão PHP 7 da classe, que mantinha o arquivo aberto entre duas gravações.

    A aplicação servidor pode atender vários clientes simultaneamente. No entanto, há um único arquivo de log para todos eles. Existe, portanto, o risco de acesso concorrente na gravação do arquivo. O curso de PHP 7 ignorava esse problema. Aqui, o flag [LOCK_EX] instrui o [file_put_contents] a bloquear o arquivo durante a gravação: se outra requisição tentar gravar ao mesmo tempo, ela espera até que o bloqueio seja liberado. Assim, uma única linha de log nunca se mistura com outra. No entanto, as linhas gravadas por duas requisições simultâneas podem ficar intercaladas entre si.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// dependências do Symfony Mailer
use Symfony\Component\Mailer\Mailer;
use Symfony\Component\Mailer\Transport;
use Symfony\Component\Mime\Email;

// envio de um e-mail ao administrador da aplicação
final readonly class SendAdminMail
{
    // $config: as informações necessárias para enviar o e-mail
    // $logger: um log opcional para registrar o resultado do envio
    public function __construct(private array $config, private ?Logger $logger = null)
    {
    }

    // envio da mensagem [$message] ao administrador
    // o método não lança exceção: uma falha no envio é apenas registrada nos logs
    public function send(string $message): void
    {
        // o e-mail é enviado ao servidor SMTP $this->config["smtp-server"] na porta $this->config["smtp-port"]
        // de $this->config["from"] para o destinatário $this->config["to"]
        // com o assunto $this->config["subject"] e os anexos $this->config["attachments"]
        // se $this->config["tls"] for true, a conexão é segura e autenticada
        $config = $this->config;
        try {
            // criação da mensagem
            $email = (new Email())
                ->from($config["from"])
                ->to($config["to"])
                ->subject($config["subject"])
                ->text($message);
            // anexos
            foreach ($config["attachments"] as $attachment) {
                if (file_exists($attachment)) {
                    $email->attachFromPath($attachment);
                } else {
                    $this->logger?->write("The attachment [$attachment] does not exist");
                }
            }
            // o transporte da mensagem
            $dsn = "smtp://{$config["smtp-server"]}:{$config["smtp-port"]}";
            if ($config["tls"]) {
                // conexão segura (STARTTLS) e autenticada
                $verifyPeer = ($config["verify-peer"] ?? true) ? 1 : 0;
                $dsn = sprintf("smtp://%s:%s@%s:%d?require_tls=1&verify_peer=%d",
                    rawurlencode($config["user"]), rawurlencode($config["password"]),
                    $config["smtp-server"], $config["smtp-port"], $verifyPeer);
            }
            // envio da mensagem
            (new Mailer(Transport::fromDsn($dsn)))->send($email);
            $this->logger?->write("Message [$message] sent to {$config["to"]}");
        } catch (\Throwable $ex) {
            // falha no envio
            $this->logger?->write("Error while sending the message [$message]: {$ex->getMessage()}");
        }
    }
}

    Comentários

    • Linhas 9–11: O curso de PHP 7 usava a biblioteca [SwiftMailer], que não é mais mantida. Usamos o [Symfony Mailer], apresentado no capítulo sobre funções de rede;
    • Linha 18: O construtor recebe dois parâmetros:
      • [$config]: um array associativo contendo todas as informações necessárias para enviar o e-mail;
      • [$logger]: um log para registrar o resultado do envio do e-mail. Este parâmetro é opcional; seu valor padrão é [null];
    • linha 24: o método [send] envia a mensagem [$message]. O código é o da função [sendmail] do script [smtp-02.php] do capítulo sobre funções de rede;
    • Linha 43: O operador null-safe [?->] (PHP 8.0) chama o método [write] somente se [$this->logger] não for [null]. Ele substitui o teste [if ($this->logger !== NULL)] do script PHP 7;
    • linha 58: o método [send] captura todos os erros: uma falha no envio do e-mail é apenas registrada em log. Um erro no tratamento de erros não deve impedir o servidor de responder ao seu cliente.

    <?php

declare(strict_types=1);

// namespace
namespace Application;

// uma camada [dao] que pode ser construída a partir de dados tributários já obtidos
class ServerDaoWithSession extends ServerDao
{
    // o construtor recebe:
    // - o nome do arquivo JSON que descreve o banco de dados: os dados tributários são lidos do banco de dados
    // - ou os próprios dados tributários, já obtidos (na sessão, por exemplo)
    public function __construct(string|TaxAdminData $source)
    {
        if ($source instanceof TaxAdminData) {
            // caso mais simples: os dados já estão disponíveis
            $this->taxAdminData = $source;
        } else {
            // repassamos à classe pai, que sabe usar o banco de dados
            parent::__construct($source);
        }
    }
}

    Comentários

    • Linha 9: A classe [ServerDaoWithSession] da versão 9 estende a classe [ServerDao] da versão 8. Isso porque a classe [ServerDao] é capaz de usar o banco de dados. Resta apenas tratar o caso em que os dados da administração tributária já foram obtidos;
    • linha 14: o construtor recebe um parâmetro que pode ser de dois tipos. O tipo união [string|TaxAdminData] (PHP 8.0) o define da seguinte forma:
      • uma string: o nome do arquivo contendo as informações necessárias para se conectar ao banco de dados, se os dados da administração tributária ainda não foram obtidos;
      • um objeto [TaxAdminData]: os dados da administração tributária, se já foram obtidos;
    • linhas 16–18: o operador [instanceof] determina qual dos dois tipos foi recebido. Se forem os dados tributários, eles são armazenados no atributo [taxAdminData], herdado da classe [ServerDao]. É por isso que esse atributo foi declarado como [protected readonly] na versão 8. A classe PHP da versão 7 tinha um construtor com dois parâmetros, um dos quais devia ser [NULL];
    • linha 21: caso contrário, o controle é passado ao construtor da classe pai, que obtém os dados do banco de dados.

    Quando uma sessão web é iniciada, a camada [dao] será construída com o nome do arquivo do banco de dados. Os dados da administração tributária serão então obtidos do banco de dados e armazenados na sessão. Nas requisições seguintes da mesma sessão, a camada [dao] será construída com o objeto [TaxAdminData] da sessão. Portanto, não haverá consulta ao banco de dados.

    <?php

// conformidade estrita com os tipos declarados dos parâmetros e resultados das funções
declare(strict_types=1);

// namespace
namespace Application;

// dependências do Symfony
use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpFoundation\Session\Session;

// os erros do PHP não são enviados ao cliente (vão para o log do servidor web)
ini_set("display_errors", "0");

// a pasta raiz do servidor: os caminhos do arquivo de configuração são relativos a esta pasta
const ROOT_DIRECTORY = __DIR__;
// caminho do arquivo de configuração
const CONFIG_FILENAME = ROOT_DIRECTORY . "/Data/config-server.json";

// recuperamos a configuração
$config = json_decode(file_get_contents(CONFIG_FILENAME), true, flags: JSON_THROW_ON_ERROR);

// incluímos as dependências necessárias ao script
require_once ROOT_DIRECTORY . "/../../../vendor/autoload.php";
foreach ($config["dependencies"] as $dependency) {
    require_once ROOT_DIRECTORY . "/$dependency";
}

// sessão (após o carregamento da classe [TaxAdminData], da qual um objeto pode estar na sessão)
$session = new Session();
$session->start();

// criação do arquivo de log
try {
    $logger = new Logger(ROOT_DIRECTORY . "/" . $config["logsFilename"]);
} catch (TaxException $ex) {
    // erro 500 sem logs - a mensagem não deve revelar a árvore de arquivos do servidor
    $message = "Failed to create the log file [{$config["logsFilename"]}]";
    doInternalServerError($message, $config["adminMail"]);
    // concluído
    exit;
}

// 1º log
$logger->write("---new request");

// recuperamos a requisição atual
$request = Request::createFromGlobals();
// autenticação apenas na 1ª vez
if (!$session->has("user")) {
    // log
    $logger->write("Authentication in progress…");
    // as credenciais enviadas pelo cliente (null se ele não enviou nenhuma)
    $requestUser = $request->getUser();
    $requestPassword = $request->getPassword();
    // o usuário é um dos usuários autorizados?
    $found = $requestUser !== null && $requestPassword !== null
        && array_any(
            $config["users"],
            fn(array $user): bool => $user["login"] === $requestUser && hash_equals($user["passwd"], $requestPassword)
        );
    if (!$found) {
        // não encontrado - código 401
        sendResponse(
            ["error" => "Authentication failed [$requestUser]"],
            Response::HTTP_UNAUTHORIZED,
            ["WWW-Authenticate" => 'Basic realm="Tax calculation server"'],
            $logger
        );
        // concluído
        exit;
    }
    // registramos na sessão que o usuário foi autenticado
    $session->set("user", $requestUser);
    // log
    $logger->write("Authentication successful [$requestUser]");
} else {
    // log
    $logger->write("Authentication taken from the session…");
}

// temos um usuário válido - verificamos os parâmetros recebidos
$errors = [];
// devemos ter uma requisição GET com três parâmetros
if ($request->getMethod() !== "GET" || $request->query->count() !== 3) {
    $errors[] = "GET method required with only the parameters [married, children, salary]";
}
// o estado civil
if (!$request->query->has("married")) {
    $errors[] = "missing married parameter";
} else {
    $married = strtolower(trim($request->query->getString("married")));
    if (!in_array($married, ["yes", "no"], true)) {
        $errors[] = "invalid married parameter [$married]";
    }
}
// o número de filhos e o salário: inteiros >= 0
$values = [];
foreach (["children", "salary"] as $parameter) {
    if (!$request->query->has($parameter)) {
        $errors[] = "missing $parameter parameter";
        continue;
    }
    $value = trim($request->query->getString($parameter));
    if (preg_match('/^\d+$/', $value) !== 1) {
        $errors[] = "invalid $parameter parameter [$value]";
    } else {
        $values[$parameter] = (int) $value;
    }
}
// há outros parâmetros na requisição?
foreach (array_diff(array_keys($request->query->all()), ["married", "children", "salary"]) as $parameter) {
    $errors[] = "invalid parameter [$parameter]";
}
// erros?
if ($errors !== []) {
    // enviamos um código de erro 400 ao cliente
    sendResponse(["errors" => $errors], Response::HTTP_BAD_REQUEST, [], $logger);
    // concluído
    exit;
}
// log
[$children, $salary] = [$values["children"], $values["salary"]];
$logger->write("valid parameters ['married'=>$married, 'children'=>$children, 'salary'=>$salary]");

// temos tudo o que é preciso para trabalhar
// criação da camada [dao]
if (!$session->has("taxAdminData")) {
    // os dados tributários são obtidos do banco de dados
    $logger->write("tax data taken from the database");
    try {
        // construção da camada [dao]
        $dao = new ServerDaoWithSession(ROOT_DIRECTORY . "/" . $config["databaseFilename"]);
        // colocamos os dados tributários na sessão
        $session->set("taxAdminData", $dao->getTaxAdminData());
    } catch (TaxException $ex) {
        // erro 500
        doInternalServerError($ex->getMessage(), $config["adminMail"], $logger);
        // concluído
        exit;
    }
} else {
    // os dados tributários são obtidos da sessão
    $dao = new ServerDaoWithSession($session->get("taxAdminData"));
    // log
    $logger->write("tax data taken from the session");
}
// criação da camada [business]
$business = new ServerBusiness($dao);
// cálculo do imposto
$result = $business->calculateTax($married, $children, $salary);
// retornamos a resposta
sendResponse($result, Response::HTTP_OK, [], $logger);
// fim
exit;

// --------------------------------------------------------------------------
// erro fatal: um e-mail ao administrador e uma resposta 500 ao cliente
function doInternalServerError(string $message, array $adminMail, ?Logger $logger = null): void
{
    // a mensagem de erro de um driver de SGBD pode não estar codificada em UTF-8 (Windows-1252 no Windows)
    if (!mb_check_encoding($message, "UTF-8")) {
        $message = mb_convert_encoding($message, "UTF-8", "Windows-1252");
    }
    // enviamos um e-mail ao administrador
    // [SendAdminMail] captura todas as exceções e as registra ela mesma
    (new SendAdminMail($adminMail, $logger))->send($message);
    // enviamos um código de erro 500 ao cliente
    sendResponse(["error" => $message], Response::HTTP_INTERNAL_SERVER_ERROR, [], $logger);
}

// envio da resposta HTTP ao cliente
// $result: o array a enviar, na forma ["response" => $result]
// $statusCode: o status HTTP da resposta
// $headers: cabeçalhos HTTP a adicionar à resposta
// $logger: o log da aplicação (null se não pôde ser criado)
function sendResponse(array $result, int $statusCode, array $headers = [], ?Logger $logger = null): void
{
    // a resposta JSON
    $response = new JsonResponse(null, $statusCode, $headers);
    $response->setEncodingOptions(JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRESERVE_ZERO_FRACTION);
    $response->setData(["response" => $result]);
    // envio
    $response->send();
    // log
    $logger?->write($response->getContent());
}

    • linha 13: é usada a classe [Session] do [HttpFoundation], apresentado no capítulo anterior;
    • Linha 16: Os erros detectados pelo PHP (avisos, erros fatais etc.) não são exibidos no documento enviado ao cliente. Eles corromperiam a resposta JSON esperada pelo cliente. São registrados no log de erros do servidor web (arquivo [error.log] do Apache);

    • Linhas 37–44: Tenta-se criar o arquivo de log. Se ocorrer uma exceção, a função [doInternalServerError] é chamada sem log (o último parâmetro é omitido). A mensagem de erro inclui o nome do arquivo de log especificado na configuração: a mensagem da exceção contém o caminho completo do arquivo, o que revelaria ao cliente a estrutura de pastas do servidor;

      • [$adminMail]: as informações necessárias para enviar um e-mail ao administrador da aplicação;

    • linha 170: um e-mail é enviado ao administrador da aplicação;

    • linha 180: a função [sendResponse] envia todas as respostas ao cliente. Seus parâmetros são:

      • depois que o cliente é autenticado, a chave [user] é armazenada na sessão, com o identificador do usuário da linha 77 como valor;

declare(strict_types=1);

// namespace
namespace Application;

// dependências do Symfony
use Symfony\Component\HttpClient\HttpClient;
use Symfony\Contracts\HttpClient\Exception\ExceptionInterface;
use Symfony\Contracts\HttpClient\HttpClientInterface;

// a camada [dao] do cliente: um cliente HTTP do servidor de cálculo de imposto que gerencia uma sessão
class ClientDao implements InterfaceClientDao
{
    // a trait da versão 5 implementa os métodos [getTaxPayersData] e [saveResults] da interface
    use TraitDao;

    // o cliente HTTP
    private readonly HttpClientInterface $httpClient;
    // o cookie de sessão (null enquanto o servidor não o tiver enviado)
    private ?string $sessionCookie = null;

    // construtor
    // $urlServer: a URL do servidor de cálculo de imposto
    // $user: o usuário que faz as requisições, array [login, passwd]
    // $httpClientOptions: opções adicionais do cliente HTTP (verify_peer, verify_host...)
    public function __construct(
        private readonly string $urlServer,
        #[\SensitiveParameter] private readonly array $user,
        array $httpClientOptions = [],
    ) {
        // o cliente HTTP: as credenciais do usuário só serão enviadas na 1ª requisição
        $this->httpClient = HttpClient::create($httpClientOptions);
    }

    // cálculo do imposto pelo servidor
    #[\Override]
    public function calculateTax(string $married, int $children, int $salary): array
    {
        // as opções da requisição: os parâmetros esperados pelo servidor
        $options = [
            "query" => [
                "married" => $married,
                "children" => $children,
                "salary" => $salary,
            ],
        ];
        if ($this->sessionCookie === null) {
            // ainda sem sessão: enviamos as credenciais do usuário
            $options["auth_basic"] = [$this->user["login"], $this->user["passwd"]];
        } else {
            // enviamos o cookie de sessão: o usuário já está autenticado nesta sessão
            $options["headers"] = ["Cookie" => $this->sessionCookie];
        }
        try {
            // fazemos a requisição ao servidor
            $response = $this->httpClient->request("GET", $this->urlServer, $options);
            // o status, os cabeçalhos e o documento JSON da resposta, mesmo em caso de erro (parâmetro false)
            $statusCode = $response->getStatusCode();
            $headers = $response->getHeaders(false);
            $json = $response->getContent(false);
        } catch (ExceptionInterface $ex) {
            // não foi possível alcançar o servidor
            throw new TaxException("Error communicating with the server ({$ex->getMessage()})", 40, $ex);
        }
        // logs
        // print "$json\n";
        // o servidor envia a string JSON de um array ["response" => algo]
        try {
            $serverResponse = json_decode($json, true, flags: JSON_THROW_ON_ERROR)["response"] ?? null;
        } catch (\JsonException $ex) {
            $serverResponse = null;
        }
        if (!is_array($serverResponse)) {
            throw new TaxException("Invalid server response [$json]", 41);
        }
        // erro?
        if ($statusCode !== 200) {
            // lançamos uma exceção cuja mensagem é a resposta do servidor completada com seu status HTTP
            $message = json_encode(
                ["HTTP status" => $statusCode] + $serverResponse,
                JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR
            );
            throw new TaxException($message, 42);
        }
        // recuperamos o cookie de sessão se ainda não for conhecido
        if ($this->sessionCookie === null) {
            foreach ($headers["set-cookie"] ?? [] as $cookie) {
                if (preg_match('/^PHPSESSID=(.+?);/', $cookie, $fields) === 1) {
                    $this->sessionCookie = "PHPSESSID=$fields[1]";
                }
            }
        }
        // retornamos a resposta: o array [tax, surcharge, discount, reduction, rate]
        return $serverResponse;
    }
}

    • Linha 41: O método [setUp] é executado antes de cada teste. Um novo [ClientDao] é, portanto, criado para cada teste, com um cookie de sessão [null]. Isso explica por que esse cliente não se beneficia de nenhuma sessão: é como se os 11 testes fossem realizados por 11 usuários diferentes.

    Este exemplo mostra que a sessão não é o lugar certo para armazenar os dados da administração tributária. De fato, esses dados são compartilhados por todos os usuários da aplicação. No entanto, neste caso, eles são duplicados em cada uma das sessões.

    Na programação web, há três tipos de visibilidade para dados compartilhados:

    • dados compartilhados por todos os usuários da aplicação web. Geralmente são dados somente leitura. O PHP não oferece suporte nativo a esse tipo de armazenamento: cada requisição é executada por um script que começa com a memória vazia;
    • dados compartilhados entre as requisições de um mesmo cliente. Esses dados são armazenados na sessão. Chamamos isso de sessão do cliente, para designar a memória do cliente. Todas as requisições de um cliente têm acesso a essa sessão. Elas podem armazenar e ler informações nela. Nos scripts anteriores, essa sessão é implementada pelo objeto Symfony [HttpFoundation\Session\Session];
    • o contexto da requisição. A requisição de um usuário pode ser processada por várias ações sucessivas. O contexto da requisição permite que a ação 1 passe informações à ação 2. Com o [HttpFoundation], a requisição é implementada pelo objeto [Request], e seu contexto é implementado por seu atributo [attributes].

    Existem ferramentas para atribuir memória de aplicação ao PHP. A nova versão do exercício de aplicação demonstra o uso de uma delas.
