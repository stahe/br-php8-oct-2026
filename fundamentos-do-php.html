// um laço

    print "array[$i]=$array[$i]\n";
}
// inicialização de 2 variáveis com o conteúdo de um array
[$string1, $string2] = ["string1", "string2"];
// concatenação das 2 strings
$string3 = $string1 . $string2;
// exibe o resultado
print "[$string1,$string2,$string3]\n";

// o tipo de uma variável pode ser conhecido

// uma função pode retornar um resultado
$res1 = f1(4);
print "res1=$res1\n";
// uma função pode retornar um array de valores
[$res1, $res2, $res3] = f2();
print "(res1,res2,res3)=[$res1,$res2,$res3]\n";
// poderíamos ter recuperado esses valores em um array
$t = f2();
for ($i = 0; $i < count($t); $i++) {
    print "t[$i]=$t[$i]\n";
}
// alguns testes
for ($i = 0; $i < count($t); $i++) {
    // exibe apenas as strings
    if (gettype($t[$i]) === "string") {
        print "t[$i]=$t[$i]\n";
    }
}
// operadores de comparação == e ===
if ("2" == 2) {
    print "with the == operator, the string 2 is equal to the integer 2\n";
} else {
    print "with the == operator, the string 2 is not equal to the integer 2\n";
}
if ("2" === 2) {
    print "with the === operator, the string 2 is equal to the integer 2\n";
} else {
    print "with the === operator, the string 2 is not equal to the integer 2\n";
}
// uma comparação cujo resultado mudou com o PHP 8
if (0 == "abc") {
    print "with the == operator, the integer 0 is equal to the string abc\n";
} else {
    print "with the == operator, the integer 0 is not equal to the string abc\n";
}
// outros testes
for ($i = 0; $i < count($t); $i++) {
    // exibe apenas os inteiros > 10
    if (is_int($t[$i]) && $t[$i] > 10) {
        print "t[$i]=$t[$i]\n";
    }
}
// um laço while
$t = [8, 5, 0, -2, 3, 4];
$i = 0;
$sum = 0;
while ($i < count($t) && $t[$i] > 0) {
    print "t[$i]=$t[$i]\n";
    $sum += $t[$i];   // $sum = $sum + $t[$i]
    $i++;             // $i = $i + 1
}
print "sum=$sum\n";

// fim do programa
exit;

    print "string=$string\n";
}

{
    // exibe o tipo de $variable
    print "type[variable $" . $name . "]=" . gettype($variable) . "\n";
}

//----------------------------------
function f1(int $param): int
{
    // soma 10 a $param
    return $param + 10;
}

//----------------------------------
function f2(): array

    // retorna 3 valores
    return ["one", 0, 100];

    Comentários:

    • linha 4: instrui o PHP a verificar estritamente os tipos declarados dos parâmetros e dos retornos das funções. Voltaremos a isso na seção sobre mudanças de tipo. Por enquanto, observe que todos os scripts deste curso começam assim;
    • linha 8: em PHP, as variáveis não são declaradas. Elas têm um tipo dinâmico, que pode mudar ao longo do tempo. [$name] representa a variável de identificador [name];
    • linha 10: para escrever na tela, pode-se usar a instrução [print] ou a instrução [echo];
    • Linha 12: a notação [[...]] serve para definir um array. A notação [$array[$i]] representa o elemento de número [$i] do array [$array], em que o primeiro elemento tem o número 0. A notação mais antiga [array("one", "two", 3, 4)] ainda é aceita, mas não a usaremos;
    • linha 14: a função [count($array)] retorna o número de elementos do array [$array];
    • linhas 16–18: um laço. Como esse laço contém apenas uma instrução, as chaves são opcionais. No restante deste documento, usaremos sempre chaves, qualquer que seja o número de instruções;
    • linha 17: as strings são delimitadas por aspas duplas " ou aspas simples '. Dentro de aspas duplas, as variáveis [$variable] são avaliadas (diz-se também “interpoladas”), mas não dentro de aspas simples;
    • linha 20: é possível atribuir os elementos de um array a várias variáveis em uma única operação. Aqui, [$string1="string1"] e [$string2="string2"]. Essa sintaxe, chamada de desestruturação, substitui a função [list] das versões antigas do PHP: [list($string1, $string2) = ...] ainda é aceito;
    • linha 22: o operador . (ponto) é o operador de concatenação de strings;
    • Linhas 91–95: a palavra-chave [function] define uma função. Uma função pode ser definida em qualquer lugar do script, até depois de ter sido usada. Aqui, [string $string] indica que o parâmetro [$string] deve ser uma string, e [: void] indica que a função não retorna resultado. Essas declarações de tipo são opcionais em PHP, mas as usaremos sistematicamente: elas documentam o código e permitem que o PHP (e o editor) detectem erros;
    • linha 98: o tipo [mixed] (PHP 8.0) significa “qualquer tipo”. O parâmetro [$variable] pode aceitar um inteiro, uma string, um array etc.;
    • linha 101: a função predefinida [gettype($variable)] retorna uma string que representa o tipo de [$variable]. Os resultados mostram que esse tipo pode mudar ao longo do tempo: [$n] é primeiro um inteiro e depois uma string;
    • linha 105: uma função retorna um resultado com a instrução [return]. O tipo desse resultado é declarado depois dos parênteses: [: int]. O código chamador pode ignorar ou recuperar os resultados de uma função;
    • linha 112: uma função pode retornar vários valores agrupando-os em um array;
    • linhas 53–62: o operador [===] faz uma comparação estrita de dois elementos: eles devem ter o mesmo tipo e o mesmo valor para serem iguais. O operador [] é menos estrito: dois elementos podem ser iguais sem serem do mesmo tipo. Nesse caso, a comparação é feita depois que ambos os elementos são convertidos para o mesmo tipo. É bastante fácil “deixar passar” essas conversões implícitas e acabar com resultados inesperados, como descobrir que uma condição é verdadeira quando se esperava que fosse falsa. Para evitar essa armadilha, usaremos sempre o operador de comparação [=] (e sua negação, [!==]);
    • linhas 64–68: um exemplo dessas conversões implícitas. No PHP 7, a string “abc” era convertida no número 0, e a expressão [0 == "abc"] era verdadeira! Desde o PHP 8.0, ao comparar um número com uma string que não representa um número, o número é convertido em string, e a expressão é falsa. O comportamento de [] mudou, portanto, de uma versão para outra: mais um motivo para preferir [=];
    • Linha 72: a função [is_int] retorna [true] se seu parâmetro for um inteiro. Da mesma forma, existem [is_string], [is_float], [is_bool], [is_array]… O operador [&&] é o E lógico. Também é possível usar os operadores lógicos [||] (OU) e [!] (NÃO). O PHP também aceita as palavras-chave [and] e [or], mas sua prioridade menor que a da atribuição pode levar a resultados inesperados: não as usaremos;
    • linha 80: um laço [while]. Ele para assim que a condição é falsa — neste caso, assim que o array termina de ser percorrido ou um elemento negativo ou nulo é encontrado;
    • Linha 88: a instrução [exit] interrompe a execução do script. As funções que vêm depois não são executadas nesse ponto, mas são reconhecidas por todo o script.

    Observe que o script não termina com a tag de fechamento do código PHP [?>] . Ela não é essencial. Além disso, em um contexto web, pode causar problemas se for seguida de espaços ou quebras de linha, difíceis de detectar porque não são visíveis em um editor de texto. A recomendação [PSR-12], aliás, especifica que ela deve ser omitida em arquivos que contêm apenas PHP. Por isso, no restante deste documento, nós a omitiremos sistematicamente.

    Nota: neste documento, usaremos a palavra-chave [print] para exibir texto no console. Outra forma de fazer o mesmo é usar a palavra-chave [echo]. Há diferenças sutis entre essas duas palavras-chave, mas, no contexto deste documento, elas não terão importância. Portanto, se você preferir usar [echo], fique à vontade.

    3.3.2. Uso do VS Code

    Para trabalhar com os scripts do curso, abra a pasta [php8-oct-2026] no [VS Code] (menu [File > Open Folder]). A árvore de arquivos aparece no explorador, no lado esquerdo da janela. Para executar um script:

    • abra um terminal integrado (menu [Terminal > New Terminal]). Ele abre na pasta [php8-oct-2026];
    • navegue até a pasta do script: [cd scripts-console/basics];
    • execute o script: [php basics-01.php]. Os resultados são exibidos no terminal. Como alternativa, no explorador de arquivos, você pode clicar com o botão direito na pasta [basics] e selecionar [Open in Integrated Terminal].

    Se o comando [php] não for reconhecido, é porque a pasta do PHP não está no PATH do Windows: o [Laragon] a adiciona lá quando você marca a opção correspondente em seu menu [Tools > Path]. O comando [php -v] deve exibir a versão 8.5.

    A extensão [PHP Intelephense] analisa o código enquanto você digita e sinaliza problemas com uma linha ondulada sob o código incorreto. Passar o mouse sobre essa linha exibe a mensagem. Todos os problemas do arquivo são listados no painel [Problems] (menu [View > Problems]). Entre os avisos úteis:

    • [Undefined variable]: uma variável está sendo usada sem ter sido inicializada. Costuma ser um erro de digitação no nome da variável;
    • [Undefined function]: está sendo chamada uma função que não existe; novamente, costuma ser um erro de digitação;
    • [Expected type 'int'. Found 'string'.]: um parâmetro efetivo não tem o tipo declarado pela função. Esse é um dos grandes benefícios das declarações de tipo: o erro é sinalizado antes mesmo da execução;
    • [Expected 2 arguments. Found 1.]: o número de parâmetros efetivos não corresponde à definição da função.

    Passar o mouse sobre o nome de uma função exibe sua assinatura (parâmetros, tipos, valor de retorno) e sua documentação, inclusive para as funções predefinidas do PHP. Para garantir que o [Intelephense] conheça as novidades recentes da linguagem, verifique as configurações do [VS Code] (menu [File > Preferences > Settings], pesquise “intelephense php version”) e confira se a versão do PHP especificada é a 8.5. Ao aprender a linguagem, convém corrigir todos os avisos relatados. É uma ótima maneira de aprender.

    O [Intelephense] também pode formatar um arquivo (clique com o botão direito, [Format Document]) segundo as recomendações de codificação da [PSR-12]. As PSR (PHP Standard Recommendations) são diretrizes para produzir código padronizado, facilitando assim a interoperabilidade e a manutenção de código escrito por pessoas diferentes. Elas são publicadas pelo [PHP-FIG] no site www.php-fig.org. As recomendações [PSR-1] e [PSR-12] estabelecem as regras de escrita do código. Eis as regras da [PSR-1]:

    Elemento
    Regra
    Constantes de classe
    As constantes de classe DEVEM ser escritas em letras maiúsculas, com o caractere _ como separador.
    Ex.: [const VAT_RATE]
    Métodos
    Os nomes de métodos DEVEM ser escritos em camelCase.
    Exemplo: [public function executeBatchTaxes()]
    Propriedades
    Os nomes de propriedades DEVEM ser escritos de forma consistente dentro de uma mesma base de código, como StudlyCaps, camelCase ou under_score.
    Exemplos: [$AnnualSalary], [$annualSalary], [$annual_salary]
    Efeitos colaterais
    Um arquivo DEVE declarar novos símbolos (classes, funções, constantes etc.) sem nenhum efeito colateral, ou executar código com efeitos colaterais, mas NÃO DEVE fazer as duas coisas.
    Tipos
    Os nomes de tipos (classes, interfaces etc.) DEVEM ser escritos em StudlyCaps. Cada tipo fica em seu próprio arquivo e em um namespace de pelo menos um nível.
    Exemplo: [class ScholarshipStudent]

    A regra dos efeitos colaterais determina que um arquivo deve conter:

    • ou declarações de tipos (classes, interfaces), funções ou constantes;
    • ou código executável sem declarações de novos tipos.

    Por simplicidade, os exemplos deste capítulo não seguem essa regra: cada script é um único arquivo que define suas funções e as utiliza. Dividir o código em vários arquivos seria trabalhoso demais para exemplos básicos. Na aplicação apresentada como fio condutor deste documento, procuraremos seguir essas recomendações o mais fielmente possível, uma vez que ela seja escrita com classes.

    • Linha 27: uma função de seta (PHP 7.4): [fn(parameters) => expression]. Ela contém apenas uma expressão, cujo valor é o resultado da função. Ela tem automaticamente acesso de leitura às variáveis do código ao redor: não há necessidade de [use]. É a maneira mais concisa de escrever pequenas funções passadas como parâmetros;
    • Linha 31: a função [usort] ordena um array usando uma função de comparação que recebe dois elementos, [$a] e [$b], e retorna um número negativo, zero ou um número positivo, conforme [$a] deva ser colocado antes, na mesma posição ou depois de [$b]. O operador [<=>] (“spaceship”) retorna exatamente -1, 0 ou 1. Ao escrever [$b <=> $a] em vez de [$a <=> $b], obtemos uma ordenação decrescente. Observe que [usort] modifica o array que lhe é passado (passagem por referência): por isso, ordenamos uma cópia ([$sorted]) do array [$numbers];
    • Linha 35: as funções [array_find], [array_any] e [array_all] foram introduzidas no PHP 8.4. [array_find] retorna o primeiro elemento para o qual a função retorna [true] (ou [null] se não houver nenhum), [array_any] retorna [true] se pelo menos um elemento satisfizer a condição e [array_all] se todos a satisfizerem;
    • linha 40: sintaxe de callable de primeira classe (PHP 8.1): [functionName(...)], com três pontos entre os parênteses, não chama a função, mas retorna a própria função como um objeto [Closure]. Ela pode então ser usada como uma função anônima;
    • Linha 43: a função predefinida [ucfirst] (primeira letra maiúscula) é passada a [array_map];
    • Linhas 46 a 49: o operador pipe [|>] (PHP 8.5). A expressão [value |> function] chama a função tendo o valor como único parâmetro. As chamadas são encadeadas da esquerda para a direita, na ordem em que são lidas: os espaços no início e no fim são removidos com [trim], o texto é convertido em minúsculas com [strtolower] e depois os espaços são substituídos por hifens. Uma função de seta usada com [|>] deve ser colocada entre parênteses;
    • linha 52: a mesma coisa sem o operador pipe. As funções são aninhadas e lidas de dentro para fora, na ordem inversa da execução.

// processamento sequencial de um arquivo de texto
// trata-se de um conjunto de linhas no formato login:pwd:uid:gid:info:dir:shell

// isso evita obter uma string vazia ao ler uma linha em branco
// abrimos o arquivo para leitura

    print "Error opening the file $INFO for reading\n";
    exit;

// o dicionário de informações
$dict = [];
// as linhas têm menos de 1000 caracteres
// a leitura da linha para na marca de fim de linha
// ou na marca de fim de arquivo
while (($line = fgets($file, 1000)) !== false) {
    // removemos a marca de fim de linha, se existir
    $line = cutNewLineChar($line);
    // colocamos a linha em um array
    $info = explode(":", $line);
    // recuperamos o login
    $login = array_shift($info);
    // ignoramos a senha (pwd)
    array_shift($info);
    // criamos uma entrada no dicionário
    $dict[$login] = $info;
}
// fechamos o arquivo
fclose($file);

// uso do dicionário
displayInfo($dict, "login10");
displayInfo($dict, "X");

// outra forma de ler um arquivo de texto: a função file
$lines = file($INFO, FILE_IGNORE_NEW_LINES);
print "the file $INFO has " . count($lines) . " lines, the last one is [" . array_last($lines) . "]\n";

// fim
exit;

// --------------------------------------------------------------------------
function displayInfo(array $dict, string $key): void
{
    // exibe o valor associado a key no dicionário $dict, se existir
    if (isset($dict[$key])) {
        // o valor existe - é um array?
        $value = $dict[$key];
        if (is_array($value)) {
            print "[$key," . implode(":", $value) . "]\n";
        } else {
            // $value não é um array
            print "[$key,$value]\n";
        }
    } else {
        // $key não é uma chave do dicionário $dict
        print "the key [$key] does not exist\n";
    }
}

// --------------------------------------------------------------------------
function cutNewLineChar(string $line): string
{
    // removemos a marca de fim de linha de $line, se existir
    // (\n no Unix, \r\n no Windows)
    return rtrim($line, "\r\n");
}

    • Linha 12: [fopen(file_name, "w")] abre o arquivo [file_name] em modo de escrita (w=write). Se o arquivo não existir, ele é criado. Se existir, seu conteúdo é apagado. O arquivo é criado no diretório atual, aquele a partir do qual o script foi executado. Se a criação falhar, [fopen] emite um aviso e retorna o valor [false];
    • linha 13: o resultado de [fopen] é testado por comparação estrita com [false];
    • linha 19: [fputs($file, $string)] escreve [$string] no arquivo [$file]. Aqui, a string termina com o marcador de fim de linha [\n];
    • linha 22: [fclose($file)] fecha o arquivo [$file];
    • linha 27: [fopen(file_name, "r")] abre o arquivo [file_name] em modo de leitura (r=read). Se a abertura do arquivo falhar (por exemplo, se o arquivo não existir), [fopen] retorna o valor [false];
    • linha 34: o dicionário é inicializado vazio antes de ser preenchido. O PHP criaria o array na primeira atribuição de [$dict[$login] = ...], mas, se o arquivo estivesse vazio, a variável não existiria e seu uso provocaria um aviso;
    • linha 38: [fgets($file, 1000)] lê a próxima linha do arquivo, limitada a 1.000 caracteres. A operação [while (($line = fgets($file, 1000)) !== false) {...}] consiste em duas operações sucessivas: 1) [$line = fgets(...)] e 2) [while ($line !== false)]. Depois que o último caractere do arquivo foi lido, a função [fgets] retorna o valor [false], e o laço [while] é interrompido. Aqui, a função [fgets] tenta ler até 1.000 caracteres, mas para assim que encontra um caractere de fim de linha. Como todas as linhas aqui têm menos de 1.000 caracteres, [fgets] lê uma linha de texto, incluindo o caractere de fim de linha. O curso de PHP 7 escrevia [while ($line = fgets($file, 1000))]: o laço seria interrompido prematuramente diante de uma última linha reduzida a "0", sem caractere de fim de linha, pois a string "0" é convertida em [false]. A comparação estrita [!== false] evita essa armadilha;
    • linha 40: a função [cutNewLineChar] remove quaisquer caracteres de fim de linha;
    • linha 44: a função [array_shift($array)] remove o primeiro elemento de [$array] e o retorna como resultado;
    • linha 46: aqui, ignoramos o resultado retornado por [array_shift];
    • Linha 58: outra maneira de ler um arquivo de texto. A função [file] retorna um array contendo todas as linhas do arquivo. Com a opção [FILE_IGNORE_NEW_LINES], os caracteres de fim de linha são removidos. Isso é mais simples do que o laço com [fgets], mas o arquivo inteiro é carregado na memória: para um arquivo muito grande, ainda é preferível ler linha a linha;
    • linha 71: a função [is_array($variable)] retorna [true] se [$variable] for um array e [false] caso contrário;
    • linha 84: o caractere de fim de linha é a string "\r\n" em sistemas Windows e "\n" em sistemas Unix. A função [rtrim($string, $characters)] remove todos os caracteres presentes em [$characters](neste caso, \r e \n) do final de [$string]. Sem o segundo parâmetro, [rtrim] remove todos os “espaços” (espaços em branco, tabulações, quebras de linha etc.); a função [trim] faz o mesmo nas duas extremidades da string.
