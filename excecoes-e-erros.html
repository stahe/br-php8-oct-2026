    7. Exceções e erros

    Quando um método de uma classe encontra um erro irrecuperável (arquivo inexistente, banco de dados não conectado, conexão de rede interrompida), ele não exibe um erro em um console (arquivo, banco de dados), mas lança uma exceção. As exceções estendem a classe [\Exception]. Além das exceções, o funcionamento interno do PHP também lança erros cuja classe base é [\Error]. Ambas as classes implementam a interface [\Throwable].

    O PHP 8 mudou fundamentalmente o tratamento de erros: muitas situações que produziam um simples aviso (e muitas vezes um resultado absurdo) no PHP 7 agora lançam um erro que pode ser capturado. Veremos isso ao longo dos exemplos.

    A interface [\Throwable] é a seguinte (veja a documentação):

    interface Throwable extends Stringable
{
    public function getMessage(): string;
    public function getCode(): int;
    public function getFile(): string;
    public function getLine(): int;
    public function getTrace(): array;
    public function getTraceAsString(): string;
    public function getPrevious(): ?Throwable;
    public function __toString(): string;
}

    As funções dos métodos da interface são as seguintes:

    Método
    Finalidade
    [getMessage]
    Retorna a mensagem de erro
    [getCode]
    retorna o código de erro (um inteiro)
    [getFile]
    retorna o nome do arquivo em que o objeto foi criado
    [getLine]
    retorna o número da linha em que o objeto foi criado
    [getTrace]
    retorna a pilha de chamadas de funções como um array
    [getTraceAsString]
    retorna a pilha de chamadas como uma string
    [getPrevious]
    retorna o objeto [Throwable] anterior (encapsulado) ou [null]
    [__toString]
    retorna uma representação em string do objeto

    Observe que a interface [Throwable] estende a interface [Stringable] discutida no capítulo sobre classes. Uma classe não pode implementar diretamente a interface [Throwable]; ela deve derivar de [\Exception] ou de [\Error].

    <?php

// respeito estrito aos tipos declarados dos parâmetros das funções
declare(strict_types=1);

// exibe a árvore das classes predefinidas que implementam a interface [Throwable]
// limitamo-nos às extensões sempre presentes no PHP 8.5:
// o núcleo (Core), a biblioteca padrão, a biblioteca SPL, JSON e Random
$extensions = ["Core", "standard", "SPL", "json", "random"];

// as classes predefinidas dessas extensões que implementam [Throwable]
$classes = array_filter(
    get_declared_classes(),
    function (string $class) use ($extensions): bool {
        $reflection = new ReflectionClass($class);
        return $reflection->isInternal()
            && $reflection->implementsInterface(Throwable::class)
            && in_array($reflection->getExtensionName(), $extensions, true);
    }
);
sort($classes);

// exibição recursiva das classes filhas da classe [$parent]
function display(?string $parent, array $classes, string $indentation): void
{
    // os filhos diretos de [$parent]
    $children = array_values(array_filter(
        $classes,
        fn(string $class): bool => (get_parent_class($class) ?: null) === $parent
    ));
    foreach ($children as $i => $child) {
        $last = $i === count($children) - 1;
        print $indentation . ($last ? "└── " : "├── ") . $child . "\n";
        display($child, $classes, $indentation . ($last ? "    " : "│   "));
    }
}

print "Throwable\n";
display(null, $classes, "");

    Comentários

    • linha 13: a função [get_declared_classes] retorna uma lista de todas as classes conhecidas neste ponto, sejam predefinidas ou não;
    • Linhas 16–18: apenas as classes predefinidas (internas) são mantidas, aquelas que implementam a interface [Throwable] e pertencem a extensões sempre presentes no PHP 8.5 (linha 9). Outras extensões adicionam suas próprias exceções (por exemplo, [PDOException] para acesso a bancos de dados, que encontraremos mais adiante);
    • linhas 24–36: uma função recursiva que exibe as classes filhas diretas da classe [$parent], depois as filhas de cada uma delas, e assim por diante. A função [get_parent_class] retorna [false] para uma classe sem pai: o operador [?:] então transforma [false] em [null];
    • linha 29: uma arrow function (PHP 7.4), uma forma abreviada de função anônima reduzida a uma expressão;
    • linha 39: começamos pelas classes sem pai: [Error] e [Exception].

    Os resultados mostram duas famílias:

    • a família [Exception]: são as exceções lançadas por bibliotecas e pelo código da aplicação. Ela inclui:
      • [ErrorException], que converte um aviso do PHP em uma exceção (vamos usá-la no final do capítulo);
      • [JsonException] (PHP 7.3), lançada por [json_encode] e [json_decode] com a opção [JSON_THROW_ON_ERROR];
      • [Random\RandomException] (PHP 8.2), disparada pelas funções de geração de números aleatórios;
      • as exceções da biblioteca SPL (Standard PHP Library), um conjunto de classes e interfaces criado para resolver problemas frequentemente encontrados pelos desenvolvedores. Elas formam duas subfamílias:
      • [LogicException] e suas derivadas: erros de programação que podem ser resolvidos corrigindo o código: argumento inválido ([InvalidArgumentException]), valor fora do intervalo esperado ([DomainException]), método inexistente ([BadMethodCallException])...;
      • [RuntimeException] e suas variantes: erros que só podem ser detectados em tempo de execução: índice fora dos limites ([OutOfBoundsException]), valor inesperado ([UnexpectedValueException]), capacidade excedida ([OverflowException])... ;
    • a família [Error]: são os erros lançados pelo próprio engine do PHP. Ela inclui:
      • [TypeError]: um valor não é do tipo esperado (parâmetro de função, atributo tipado, valor de retorno, operando de um operador etc.). Sua derivada, [ArgumentCountError], indica um número insuficiente de argumentos;
      • [ValueError] (PHP 8.0): um valor é do tipo correto, mas tem um valor inválido (por exemplo, um comprimento negativo ou zero);
      • [ArithmeticError] e sua derivada [DivisionByZeroError]: erros em operações aritméticas;
      • [UnhandledMatchError] (PHP 8.0): nenhum ramo da expressão [match] é adequado;
      • [AssertionError]: falha na asserção [assert];
      • [CompileError] e sua derivada [ParseError]: erro de sintaxe em um arquivo carregado por [require] ou [include];
      • [FiberError] (PHP 8.1) e [Random\RandomError] (PHP 8.2): erros relacionados a fibers e a geradores de números aleatórios, que não utilizaremos.

    As duas famílias não têm relação entre si: uma cláusula [catch (\Exception $e)] não intercepta um erro [Error]. Apenas a interface [Throwable] as une.

    <?php

// respeito estrito aos tipos declarados dos parâmetros das funções
declare(strict_types=1);

// exibimos todos os erros
error_reporting(E_ALL);
ini_set("display_errors", "1");
// envolvemos o código em um try / catch
try {
    $var = [];
    // chave desconhecida
    print $var["abcd"];
    // divisão por zero
    $var = 7 / 0;
    var_dump($var);
    // array de limites fixos
    $array = new \SplFixedArray(5);
    $array[1] = 2;
    $array[4] = "foo";
    // índice fora dos limites
    $array[5] = 8;
    // verificação
    print "this message will not be displayed\n";
} catch (\Throwable $ex) {
    // \Throwable é a interface implementada por todos os erros e exceções
    // exibimos a exceção
    print "error, message: " . $ex->getMessage() . ", type: " . $ex::class . "\n";
}

    Comentários

    • O script é o apresentado no parágrafo anterior. No entanto, agora colocamos o código que pode causar erros dentro de uma estrutura [try / catch]: se o código das linhas 11–24 causar (lançar) uma exceção ou um erro, ele será tratado pela cláusula [catch] das linhas 25–29;
    • Linha 25: o parâmetro da cláusula [catch] é o tipo de exceção ou erro a tratar. Ao definir o tipo como [\Throwable], que é uma interface, indicamos que queremos tratar qualquer instância de classe que implemente a interface [\Throwable]. Como todas as classes de erro e de exceção implementam essa interface, a cláusula [catch] trata aqui todos os erros e exceções;
    • linha 15: a instrução que dispara o erro. Assim que ocorre uma exceção, o controle é transferido para a cláusula [catch]. O código que vem em seguida em [try] não é, portanto, executado;
    • linha 28: a notação [$ex::class] retorna o nome da classe do objeto [$ex].

    7.7. A cláusula [finally]

    A estrutura [try / catch] pode ter um terceiro elemento e tornar-se uma estrutura [try / catch / finally]. O código da cláusula [finally] é executado nos dois casos seguintes:

    • a cláusula [try] não lança uma exceção. Ela é então executada por inteiro, após o que a execução passa para a cláusula [finally], que é executada por inteiro;
    • a cláusula [try] lança uma exceção. Ela é então executada até a instrução que lança a exceção. A execução passa então para a cláusula [catch], que é executada por inteiro. Em seguida, a execução passa para a cláusula [finally], que é executada por inteiro.

    Por fim, o código da cláusula [finally] ainda é executado. Esse cenário é útil no seguinte caso:

    • Na cláusula [try], o código adquiriu recursos (arquivos, bancos de dados, conexões de rede, filas). Esses recursos geralmente são caros. Eles devem, portanto, ser liberados (na maioria das vezes dizemos “fechados”) o mais rápido possível;
    • se os recursos foram adquiridos em [try], sua liberação será feita em [finally]. Isso garante que, em todos os casos (ocorrendo ou não um erro), os recursos adquiridos sejam devolvidos ao sistema.

    return is_int($age) && $age >= 0 ? $age : throw new \DomainException("Invalid age [$age]");
}

// uma arrow function que apenas lança uma exceção
$forbidden = fn(string $operation) => throw new \LogicException("Operation [$operation] forbidden");

// dados de teste
$tests = [["age" => 48], [], ["age" => -4]];
foreach ($tests as $i => $data) {
    try {
        print "test $i: age=" . readAge($data) . "\n";
    } catch (\InvalidArgumentException | \DomainException $ex) {
        // uma única cláusula [catch] para dois tipos de exceção
        print "test $i: " . $ex::class . ": " . $ex->getMessage() . "\n";
    }
}

try {
    $forbidden("deletion");
} catch (\LogicException) {
    // desde o PHP 8.0, a variável da cláusula [catch] é opcional
    print "the operation was refused\n";
}

// encapsulamento de uma exceção de baixo nível em uma exceção da aplicação
class DaoException extends \RuntimeException
{
}

function readConfiguration(string $json): array
{
    try {
        return json_decode($json, true, flags: JSON_THROW_ON_ERROR);
    } catch (\JsonException $ex) {
        // a causa original é passada como 3º parâmetro: ela não se perde
        throw new DaoException("Unreadable configuration", 10, $ex);
    }
}

try {
    readConfiguration('{"dsn": "mysql:host=localhost"');
} catch (DaoException $ex) {
    print $ex::class . ": " . $ex->getMessage() . " (code " . $ex->getCode() . ")\n";
    print "cause: " . $ex->getPrevious()::class . ": " . $ex->getPrevious()->getMessage() . "\n";
}

    Comentários

    • Linha 9: a partir do PHP 8.0, [throw] é uma expressão e não mais apenas uma instrução. Ela pode, portanto, ser usada onde quer que um valor seja esperado: aqui, após o operador [??]. Se a chave [age] não existir, uma exceção é lançada; caso contrário, [$age] recebe o valor dela;
    • linha 10: [throw] usado em uma expressão condicional [? :];
    • linha 14: uma arrow function cujo corpo simplesmente lança uma exceção. Antes do PHP 8.0, isso não era possível: uma arrow function só pode conter uma expressão;
    • linha 21: uma única cláusula [catch] para dois tipos de exceção (linhas 3–4 dos resultados). Observe que [InvalidArgumentException] e [DomainException] derivam ambas de [LogicException]: um [catch (\LogicException $ex)] teria tido o mesmo efeito;
    • linha 29: a partir do PHP 8.0, a variável da cláusula [catch] é opcional quando não precisamos da exceção em si, apenas do seu tipo (linha 5);
    • linhas 35–37: uma exceção específica da aplicação. Nos próximos capítulos, escreveremos camadas de acesso a dados (DAO, Data Access Object) que lançarão apenas esse tipo de exceção, independentemente da origem do erro (arquivo, JSON, banco de dados);
    • linhas 39–47: a função [readConfiguration] decodifica uma string JSON. A exceção de baixo nível [JsonException] é interceptada e encapsulada (linha 45) em uma exceção [DaoException]. A causa original é passada como terceiro parâmetro ao construtor;
    • linha 53: o código chamador conhece apenas [DaoException], mas pode recuperar a causa original do erro por meio do método [getPrevious] (linhas 6–7 dos resultados).

    7.13. Converter avisos em exceções: [ErrorException]

    Apesar das melhorias do PHP 8, certas anomalias continuam sendo meros avisos: chave de array inexistente, variável não definida, arquivo que não pode ser aberto com [fopen]... Esses avisos não podem ser interceptados por um [try / catch]. No entanto, é possível instalar um manipulador de erros que os converte em exceções [ErrorException]. É isso que o script [exceptions-11.php] faz:

    <?php

// respeito estrito aos tipos declarados dos parâmetros das funções
declare(strict_types=1);

// manipulador de erros: transforma os avisos do PHP em exceções [ErrorException]
set_error_handler(function (int $level, string $message, string $file, int $line): bool {
    throw new \ErrorException($message, 0, $level, $file, $line);
});

// uma chave desconhecida não causa mais um simples aviso, mas uma exceção
$person = ["lastName" => "Langevin"];
try {
    print $person["firstName"] . "\n";
} catch (\ErrorException $ex) {
    print "Error: " . $ex->getMessage() . " (line " . $ex->getLine() . ")\n";
    print "level E_WARNING: " . var_export($ex->getSeverity() === E_WARNING, true) . "\n";
}
// o mesmo vale para a abertura de um arquivo inexistente
try {
    $stream = fopen(__DIR__ . "/nonexistent.txt", "r");
} catch (\ErrorException $ex) {
    print "Error: " . $ex->getMessage() . "\n";
}
// voltamos ao manipulador de erros do PHP
restore_error_handler();
print "end\n";

    Comentários

    • Linhas 7–9: a função [set_error_handler] define um manipulador de erros, uma função que o PHP chamará sempre que ocorrer um aviso, uma nota ou uma depreciação, em vez de exibir a mensagem. Ela recebe o nível do erro, a mensagem de erro, o arquivo e a linha em que o erro ocorreu. Aqui, ela lança uma exceção [ErrorException] que armazena essas informações. O tipo de retorno [bool] é o especificado na documentação de [set_error_handler]: a função retornaria [false] para deixar o PHP tratar o erro normalmente. Aqui ela nunca retorna nada, pois sempre lança uma exceção;
    • linha 14: a chave [firstName] não existe. Em vez de um aviso, é lançada uma exceção [ErrorException], que é capturada (linha 2 dos resultados);
    • linha 17: o método [getSeverity], específico da classe [ErrorException], retorna o nível do erro original (linha 3);
    • linha 21: tentar abrir um arquivo inexistente também resulta em uma exceção (linha 4);
    • linha 26: restaura o manipulador de erros anterior, neste caso o do PHP.

    Essa técnica é usada por muitos frameworks PHP (Symfony, Laravel): durante o desenvolvimento, qualquer aviso se torna uma exceção, o que obriga o desenvolvedor a corrigir o código. A ferramenta de testes [PHPUnit] que usaremos mais adiante funciona de maneira semelhante: ela pode fazer um teste falhar se ele produzir um aviso ou uma depreciação.
